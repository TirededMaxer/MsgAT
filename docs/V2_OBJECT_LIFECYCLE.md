# V2 加密对象生命周期

2026-11-09 源码检查点。根种子、硬件封装和对象密钥派生保持不变。本轮仅修改源码与文档，没有构建、安装、启动客户端或进行运行验收。

## 暂存与引用

三端新增 SQLCipher 内的 `media_staging` 与 `media_garbage`。暂存记录只含随机对象 ID、当前数据库实例的所有者标记和时间；回收记录只含对象 ID、重试次数及下次重试时间。没有明文任务文件，也不在这些表重复保存内容密钥、下载凭据或文件名。

本地文件导入、剪贴板字节导入及重新加密副本都先登记暂存，再创建密文文件。准备完成后只返回对象清单，暂存仍保留；对象清单、消息/收藏引用、发送队列与暂存移除由最终的同一次事务提交。此前普通导入提前持久化无主对象清单的流程已移除。

失败或取消时，清理前先检查对象清单及全部现有引用。已被成功消息或收藏持有的文件不会因为延迟到达的失败回调而被删除。失败副本优先利用已经持久化的暂存记录删除文件，再清理记录，避免磁盘已满时必须先写另一条日志才能释放空间。文件繁忙或无法删除时，转入可重试回收；若数据库也无法写入，保留原暂存记录，供下次启动恢复。

`media_object_references` 统一列出消息附件、收藏、用户头像、消息/收藏预览封面、传输任务和活动传输保护的引用，相关对象 ID 均有索引。视图在资料库启动、工作器运行前重新建立，以应用当前定义。头像已有引用覆盖；以后添加贴纸或其他媒体所有者时，必须先扩展此视图，再允许回收器处理对应对象；当前文档不把这些尚未完成的模块算作已覆盖。

头像与普通附件共用 `object_transfers`，不再强制要求存在消息行。活动传输通过 `object_transfer_pins` 保留文件，防止更换头像或删除消息时，下载与文件回收交错产生无主文件；退出或重开时释放或恢复该保护。参见[资料与头像](V2_PROFILES.md)。

## 启动恢复与回收

每个资料目录都有独占进程锁。Mac 使用 `flock`，Android 使用文件通道锁，在身份恢复前获取并持有到进程退出。Windows 启动时先获取应用实例互斥锁，打开数据库后另持有资料库的独占文件句柄。锁负责在实例之间协调启动、重置和数据库访问。

每个打开的数据库实例有一个运行期所有者标记。重启后，旧所有者的暂存转入回收队列；当前仍在使用的暂存不会被启动恢复当成遗留文件。一次有界扫描也处理数据库中早期版本留下的无引用对象清单，删除清单时的触发器将对应对象加入回收。

回收前在同一数据库事务内再次检查清单、引用和暂存。只有没有任何这些保护的对象才调用共享 Rust 核心的 `remove_object_files`；文件删除完成后才移除回收记录。每批最多 64 个对象，有积压时在批次间让出执行时间；空闲检查间隔为 30 秒。失败保留记录，退避时间最长五分钟。

删除操作只接受 64 位小写十六进制对象 ID，生成三个确切路径：最终 `.obj`、本地加密写入的 `.part`、下载恢复的 `.obj.part`；不接收任意相对文件名，不递归删除目录，也不处理显式导出的文件。Unix 使用固定目录描述符上的 `openat`/`unlinkat`，拒绝符号链接目录，并在删除后同步目录。Windows 固定目录句柄、拒绝目录重解析点，打开叶节点时使用 `FILE_FLAG_OPEN_REPARSE_POINT`，以文件句柄设置删除状态。[Microsoft 目录句柄](https://learn.microsoft.com/en-us/windows/win32/fileio/obtaining-a-handle-to-a-directory)、[重解析点行为](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[按句柄删除](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)

新绑定使用锁文件中已存在版本的 `libc` 与 `windows-sys`，没有引入新的包版本。原生库须在最终统一构建时重新生成，旧二进制不具备新增删除操作。

## 空间与关闭

普通导入与副本创建均检查密文字节数及 256 MiB 余量。转发另外计算全部独立收件人副本的总量。接收下载按未完成的密文字节计算，保留已有分块用于恢复，不把已下载部分再次计为空间需求。这些检查不预留磁盘容量；后续写入失败仍保留原消息、源文件和恢复记录。

收到的链接封面和附件一起计入可清理缓存及自动下载额度。清理或重新下载只处理由收到的消息单独持有的对象。收藏、贴纸、头像、待发消息和活动传输等引用继续保护对应文件。已标记下载完成但无法读取的链接封面，可从原消息点击重试。三端在同一个事务中重新核对当前封面引用、登记缓存移除并请求下载，待旧密文移除后才重新传输。正文、链接及同条消息的其他附件保留。

三端储存用量按照片、视频、音频、文件和链接封面显示可清理字节数。每个对象只计入一个类别。确认时显示所选类别的合计大小，提交事务重新核对对象是否仍可清理，仅登记所选类别。正文与附件记录保留，文件移除继续走已有队列。中继保留期已过的附件可能无法重新下载。分类统计和清理待统一构建及实机验收。

三端在登记下载保护的同一次事务中检查自动下载额度。额度计算包含已接收对象、尚未移除的旧缓存和其他正在下载的消息对象。对象下载完成后，即使保护记录尚未释放，也计入已接收缓存。手动下载仍可超过自动下载额度，并受磁盘可用空间检查约束。

存储用量把可清理的缓存与自动下载额度分别显示。启用额度时，进度条和剩余空间按下载队列使用的同一公式计算，包含受引用保护的接收缓存、待移除文件和已预约的下载空间。附件或链接封面的传输进度会触发刷新。

三端的 `media_thumbnail_cache` 保存原件和独立加密缩略图的关联。创建缩略图先登记暂存，提交时再次确认原件已落盘且仍有正式引用。对象清单、缩略图引用和暂存移除在同一事务内提交。`media_object_references` 只加入缩略图对象 ID，关联不会阻止原件回收。原件删除、本机缓存移除、缩略图替换及超出容量时，经现有对象垃圾队列清理派生文件。接收对象的分类用量和自动下载额度一并计算派生文件的密文字节。退出时停止接收任务并等媒体工作完成再关闭资料库。

Windows 等待整个导入到消息提交的任务及存储维护结束后，才关闭数据库。Android 导入归安全协调器管理，调用方保留临时文档权限直到该操作结束；关闭时等待导入、媒体、转发和串行处理器结束。Mac 停止维护器、转发队列和媒体工作器，再排空导入/协议回调。数据库关闭失败时不得提前释放仍在使用的数据库密钥。Mac 的资料库打开/锁定失败改为启动错误界面，保留旧资料，不再直接调用 `fatalError`。

## 验收与边界

统一构建后需要实际确认：文件与字节导入成功/失败、取消和离开聊天、收藏独立性、清历史/撤回、强制结束后重新打开、文件占用、空间不足、重复启动及退出/Reset。当前没有这些新实现的运行证据。

此回收处理拥有数据库记录或暂存记录的对象，以及可从早期对象清单确定归属的文件。完全没有清单、暂存或回收记录的旧文件不会被盲目删除；当前重构中的旧测试资料在最终专门清理时处理。缓存恢复需要中继仍保有可下载副本。本机唯一的附件、贴纸和收藏副本发生损坏时，没有远端缓存恢复来源。

## Contact permission changes during transfer

The latest source checks exact job ownership, owner revocation, accepted/request permissions and the connection epoch before each new bulk chunk, and checks ownership/permissions again in the final lease/availability transaction. A block pauses retained incoming jobs; canceled outgoing envelopes lose their jobs. Explicit contact/history deletion clears the corresponding jobs and owners. In-flight pins stay held until the operation exits, including a permission pause. A network exchange already in progress cannot be recalled. These paths remain part of unified real-client acceptance; no runtime validation was started for this source change.


## 定时与重试所有者（2026-11-10，未构建/验收）

新增 `scheduled_objects` 和 `message_send_objects`，三端引用视图与回收触发器均包含它们。前者持有未释放定时内容；后者持有未确认送达消息的原始媒体与封面，避免编辑当前消息后原事件无法重试。定时释放先创建正文/上传所有者再删除定时所有者，同一事务内完成；送达、撤回和删除通过 FK/触发器删除不再需要的重试所有者。媒体仍先 staging 后文件，提交所有者与 staging 删除共用事务，不绕过既有资料库租约、传输 pin 或退出排空。详见[发送控制](V2_SEND_QUEUE.md)，功能界面与实际生命周期验收尚未完成。


## 直接发送准备观察者

直接媒体/剪贴板/表情发送的新增准备控制器只持有进程内取消标记、阶段和 Rust 字节计数句柄，见[准备控制](V2_PREPARATION.md)。它不是媒体所有者，不创建新的引用表；对象仍由 staging 或同一提交事务中的消息/定时记录持有。取消先请求 worker 停止，在其失败副本清理结束后才关闭句柄。界面停止轮询不提前关闭资料库、释放外部文档权限或销毁硬件根保护。进度查询不触碰资料库/根密钥；真正的加密/写入仍受原操作所有权与独占租约约束。最新源码尚未构建或实机验收。

## 录制暂存接入补充（2026-11-10）

共享核心新增 `open/read/write/sync/freeze/status/close_capture_file` 操作，用既有随机对象 ID 的 `.part` 文件保存可回写的认证密文。它不是可发送对象，宿主必须在创建前登记 `media_staging`，冻结后通过已有导入产生新的最终对象，关闭原生句柄后才回收原暂存。没有新增持久媒体拥有表。

当前只是共享核心源码，三端录制拥有者及退出/Reset 排空尚未接入；不得绕过这些接入要求启用后台录制或将候选清单当作消息提交。说明见[拍摄与录制](V2_CAPTURE.md)。本补充没有构建或运行证据。
