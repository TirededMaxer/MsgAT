# V2 服务端部署与运行

本文对应未发布的 V2 源码，不能用于证明三端及全部功能已完成。已发布的 V1 包应使用其 Git 标签内的文档；V1 客户端不能连接 V2 中继。开发与实际验收状态见 [REBUILD_STATUS.md](REBUILD_STATUS.md)。

## 启动和路径

使用 Java 21。当前源码构建产物可按以下命令启动，不使用 `-noverify`：

```bash
java -jar MsgAT_Console-1.1-obfuscated.jar
```

服务端只从 **JAR 所在目录** 读取 `server-config.json`。缺失时创建以下默认配置；已有配置不会被覆盖。配置错误、重复/未知字段或非法数值会阻止启动。

```json
{
  "port": 34478,
  "listenAddress": "*",
  "dataDirectory": "data",
  "maxConnections": 1024,
  "maxUnauthenticatedConnections": 64,
  "maxUnauthenticatedPerAddress": 16,
  "maxInboundFrameBytes": 262144,
  "authenticationTimeoutSeconds": 30,
  "readTimeoutSeconds": 300,
  "writeTimeoutSeconds": 60,
  "mailboxRecipientQuotaBytes": 67108864,
  "mailboxGlobalQuotaBytes": 2147483648,
  "mailboxRetentionDays": 7,
  "attachmentMaxBytes": 104857600,
  "attachmentOwnerQuotaBytes": 536870912,
  "attachmentGlobalQuotaBytes": 8589934592,
  "attachmentRetentionDays": 14
}
```

端口范围 1–65535，默认 34478。`listenAddress` 默认 `"*"`，沿用系统的通配监听，可指定 `"127.0.0.1"`、`"::1"` 或服务器网卡上的 IP。修改后重启生效。相对 `dataDirectory` 也按 JAR 目录解析，独立于终端工作目录。程序内部会据此设置存储路径，不再用旧的命令行端口或 `-Dmsgat.data.dir` 覆盖配置。不要让多个进程同时使用同一个数据目录。

可选字段 `logLevel` 设置服务端根日志级别，支持 `TRACE`、`DEBUG`、`INFO`、`WARN` 和 `ERROR`。省略时使用 Logback 配置，发行包默认 `INFO`。

V2 不读取 V1 资料库，也不使用旧的内置数据库对称密钥、`MSGAT_DATABASE_KEY` 或 `database.key`。当前数据分为：

| 内容 | 位置与性质 |
| --- | --- |
| 签名公钥目录与幂等预留 | `msgat_v2_directory.db`；公钥、签名及必要状态，不包含客户端私钥 |
| 待投递消息 | `msgat_v2_relay.db`；端到端密文及必要路由/期限元数据 |
| 附件索引 | `msgat_v2_objects.db`；所有者、能力令牌哈希、密文长度/哈希、游标与期限 |
| 附件文件 | 随机对象编号分片的密文；没有文件名、内容密钥或明文正文 |

服务器仍能接触连接地址、路由关系、密文大小和时间等元数据。内容密钥只在客户端的加密存储和端到端事件中存在；这不等于服务器元数据对系统管理员不可见。运行时应使用专用低权限系统身份及私有数据目录。

## TLS

未设置证书时会生成临时自签名证书，重启后可能改变。V2 客户端默认验证系统信任链，或使用手动配置的 SHA-256 证书指纹；临时证书不是可持续部署的固定身份。开发证书兼容选项需要显式启用，不要把其等同于服务端身份认证。

需要稳定证书时，在 `server-config.json` 同时添加以下两个字段。支持绝对路径。相对路径以 JAR 所在目录为基准。

```json
{
  "tlsCertificatePath": "tls/fullchain.pem",
  "tlsPrivateKeyPath": "tls/privkey.pem"
}
```

JSON 未指定这两个字段时，也可使用环境变量。环境变量中的相对路径以启动进程的工作目录为基准。

```bash
export MSGAT_TLS_CERT=/path/to/fullchain.pem
export MSGAT_TLS_KEY=/path/to/privkey.pem
java -jar MsgAT_Console-1.1-obfuscated.jar
```

证书和私钥必须在同一配置来源成对指定，无法读取或加载时启动失败。TLS 保护连接，单聊和附件由客户端端到端加密。认证绑定角色、随机挑战和实际 TLS 证书指纹，完整格式见 [V2_PROTOCOL.md](V2_PROTOCOL.md) 与 [V2_ATTACHMENTS.md](V2_ATTACHMENTS.md)。

## Android 推送唤醒

在 `server-config.json` 中添加 `"pushOrigin": "https://push.example.org"`。填入 ntfy 的 HTTPS 源地址，可带端口。手机上的 ntfy 也设置该地址。省略该字段时，中继只提供原有的密文投递。

请使用专用于分发的 ntfy 实例。中继只向配置地址上符合 ntfy 格式的 UnifiedPush 订阅主题发 HTTPS POST。ntfy 需要允许中继发布和分发器订阅对应主题。客户端先接收并回传 Web Push 加密挑战，证明订阅可用。中继用有界工作线程合并唤醒并重试，记录订阅及到期时间。过期或身份撤销会清除订阅。

唤醒轮询通过索引挑选等待验证挑战或有密文积压的订阅。入队以及移除最后一条密文时，订阅的待处理标记与密文在同一事务里更新。实际唤醒仍要求有未过期的密文已超过在线直投的等待时间，或存在待发送的验证挑战。升级时从现有队列初始化标记，不必重新注册订阅。

无有效密文的收件箱重新收到消息时，中继会登记新一批待收密文。旧批次的成功响应只更新旧批次的合并时限，以免推迟新消息或来电的唤醒。分发器出现网络或服务错误时，仍对同一订阅执行失败退避。

启用该功能后，数据目录另含与身份关联的 ntfy 主题、Web Push 加密材料和仅用于唤醒认证的密钥。消息仍按原流程端到端加密入队。部署要求及设备行为见 [Android 后台接收](V2_ANDROID_BACKGROUND.md)。

## 资源和持久化

启动中途失败时，服务端会关闭此前已打开的存储和推送资源。正常停机先停止监听、关闭客户端连接并等待网络和业务执行器退出，再停止后台清理并关闭存储。

身份撤销清理在服务端启动和撤销记录落盘时安排。每批最多处理八个身份，并按数据库记录的最早重试时间安排下一批。没有待清理记录时停止轮询。撤销凭据落盘后立即生效，连接关闭与确认无需等待清理结束。

- 网络循环与业务/附件执行器分离。当前接收线程 1 个，网络工作线程 2–8 个，控制执行器 2–4 个、每线程队列 64，附件执行器 2 个、每线程队列 16。
- 控制与附件共用配置端口但使用独立认证连接；附件连接不替换账号的在线控制路由。
- 服务端在安装 TLS 处理器前计入连接预算。默认最多 1024 个连接，其中最多 64 个待认证、同一来源 IP 最多 16 个待认证。认证后释放待认证名额，断开后释放连接名额。可在同目录 JSON 设置 `maxConnections`、`maxUnauthenticatedConnections` 和 `maxUnauthenticatedPerAddress`。来源 IP 按服务端实际看到的 TCP 对端计算。
- `authenticationTimeoutSeconds` 默认 30 秒，范围 5–120，覆盖从接收连接到完成身份认证的总时间。`readTimeoutSeconds` 默认 300 秒，范围 240–3600，给客户端 180 秒心跳留出余量。新增的 `writeTimeoutSeconds` 默认 60 秒，范围 10–600，单次套接字写入超过该时间仍未完成就关闭连接。断开前未获确认的密文按原队列规则保留。
- 协议帧最大 256 KiB，发送时最小填充到 4096 字节。配置 `maxInboundFrameBytes` 可将中继入站上限设为 131072–262144 字节，默认 262144。降低后，超过新上限的客户端帧会导致该连接断开。已经入队的密文继续按协议上限投递。每连接待写线格式预算 4 MiB，慢连接关闭后未确认消息保留在持久队列中。
- 重连补收每批最多读取八条密文。当前批次所有写入成功、套接字恢复可写且连接待写量降到 1 MiB 后才读取下一批；通过写入完成和可写状态事件恢复。批次写完仅推进本次补收游标，客户端确认后才从持久队列删除。已撤销发送方的队列项按批清理。
- 已同步的在线连接在写入正常时直接收取新消息。遇到积压时，从第一条未直接送出的持久记录开始按同样的批次规则继续投递。此期间如果客户端主动请求完整同步，服务端在当前批写完后从队列起点补收，并按协议发送同步结束标记。
- 收件确认按控制连接合并。同批内的重复确认合并，累计 32 条或等待 20 ms 后提交。处理下一次显式同步前提交已有确认，断开连接时也尝试提交。提交失败时保留密文，由后续重连补收和客户端去重处理。
- 密文消息默认每收件箱 64 MiB、全局 2 GiB，可在同目录 JSON 中设置 `mailboxRecipientQuotaBytes` 和 `mailboxGlobalQuotaBytes`。单收件箱至少要能放下最大密文及其 1024 字节开销，全局上限至少等于单收件箱上限。降低上限不会删除未过期消息，超过上限的队列继续投递，空间回收前拒绝新的入队请求。
- 配额不足时，当前入队事务最多尝试回收 16 条过期密文。先处理已满的收件箱，若该收件箱已有空间但全局仍超限，剩余批次额度可用来清理全局过期项。仍没有空间则拒绝本次入队，清理继续由后台任务处理。SQLite 使用 WAL 与 `synchronous=FULL`，服务端确认在事务提交之后发出。
- 密文从入队起默认保留七天。`mailboxRetentionDays` 可设为 1–7 天，修改后重启，只影响之后入队的密文。七天上限与客户端旧接收密钥和附件租期匹配。已入队的密文沿用原到期时间，旧版中继库的记录按原入队时间加七天计算。
- 密文到期后停止投递和触发 Android 唤醒。每轮最多清理 128 条密文和 256 条过期推送订阅。任一批清满时，两秒后再处理下一批，其余情况下间隔一分钟。相同密文在到期前重试沿用原到期时间；已到期的记录若被重新提交，服务端核对密文后在同一事务内按当前期限重新入队，并分配新游标。公钥预留仍按七天清理。
- 公钥目录每轮最多清理 64 份到期的公钥包和 128 份超过七天的预留结果。单次发布或领取会复用预密钥查询，重复发布相同密钥不再尝试写入。公钥包到期后保留已使用的预密钥编号和登记记录，以防同一密钥再次被分配。
- 公钥目录使用启动时生成的随机代际。正常重启或离线恢复目录数据库后，只有当前代际签名发布的一次性预密钥可分配。旧包未过期时可用签名预密钥和 ML-KEM 最后备用密钥建立会话。客户端重连后自动发布新包。恢复操作使用已停止的中继实例，客户端和中继使用相同版本。 [协议说明](V2_PROTOCOL.md#signed-public-directory)
- 安卓后台唤醒查找按收件人和入队时间使用索引。过期订阅按到期时间使用索引分批清理。
- 收件箱和全局用量随密文增删在同一事务中更新。首次升级或发现配额计数状态缺失、不一致时重算，重算和触发器启用共用一个事务。日常重启复用计数，省去对全部密文记录的聚合扫描。
- 公钥目录使用独立常驻连接与 1 MiB 页面缓存；中继库页面缓存 2 MiB。目录不再依赖旧用户资料库。
- 附件按完整密文大小及元数据预占配额，采用 64 KiB 明文分块对应的认证密文块；断点游标、完成确认、租期与回收见附件协议。保留期允许 8–30 天，默认 14 天。
- 附件分块复用连接上的对象查询、上传游标更新及身份撤销查询语句。每次请求仍读取当前记录，写入分块仍先同步文件再提交数据库游标。
- 附件配额随对象增删在同一事务内维护。升级时重算一次。常规重启核对全局用量、各所有者用量及触发器，发现计数缺失或不一致时才重新扫描对象记录。
- 附件清理通过同一索引查找租期已到的对象，以及连续 24 小时没有写入新分块的未完成上传。每轮最多清理 16 个。公钥预留每轮最多清理 1000 条。两项均在清满一批后间隔两秒继续处理，低于批次上限时恢复一分钟间隔。

这些是实现中的预算，不是生产吞吐或并发容量证明。内存、CPU 和网络表现仍需真实客户端传输及部署负载验证；本地空闲进程数据不能用于承诺服务器容量。

## 尚未完成的边界

服务端处理 V2 公钥目录、密文投递、附件和身份撤销。通话控制经密文队列投递。收到旧版或未知操作时关闭连接。上线验收仍需覆盖目录更新、接收端长期离线、撤销清理、资源配额和三端重连。
