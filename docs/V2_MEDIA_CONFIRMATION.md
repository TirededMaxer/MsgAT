# 附件发送确认

三端已有单附件和多附件发送确认源码，等待统一编译和实机验收。

文件和图库选择、桌面拖放及桌面文件列表粘贴先进入原生确认界面。界面显示收件人、文件名、可取得的大小和有界图片预览，可填写说明、选择按文件发送、设置定时或静默发送。取消确认不启动对象导入，也不消费聊天草稿或回复。

桌面粘贴文件列表和拖放使用同一套流程。文件夹在原批次位置打开系统选择器，由用户挑选文件；取消只跳过该文件夹。剪贴板同时提供系统文件列表和图片时，优先按文件列表进入确认。

从「文件」选取时，三端默认按文件发送，确认前可以更改。安卓图库在确认前支持浏览及批量选择，取消确认保留附件面板中的选择顺序。Windows 与 Mac 选择文件前先绑定会话和引用。安卓发送确认通过返回或取消键退出，已填写说明时先给出丢弃确认。

在聊天输入框粘贴图片时，Windows 和 Mac 将剪贴板图片直接送入当前会话的加密发送队列。Android 对系统显式授予读取权限的图片执行同样操作，一次最多十张，多张按相册入队。其他可识别但没有该授权的图片仍显示发送确认。直接粘贴保留已有输入文字，并使用粘贴当时的引用和发送选项。

确认界面将收件人放在顶部，说明、发送选项和确认按钮固定在底部。底部附件菜单集中提供按文件发送、相册及图片和视频压缩，可在预览滚动到任意位置时调整。单项有可用预览时显示大图，选为相册时三端显示双列预览，奇数项的首张横跨整行。相册和独立附件布局切换时按各平台的动画设置过渡。两种布局都可以排序、移除和编辑支持的媒体。安卓可向系统请求选定视频的缩略图，系统无法提供时显示视频图标。

确认时保存此次来源、收件人、回复与发送选择；异步准备仍使用对应会话的草稿令牌。说明作为 `chat.attachment.caption` 进入原有 Signal 加密正文和 SQLCipher 消息/附件记录，UTF-8 上限 48 KiB。按文件发送使用 application/octet-stream，不改变文件字节、文件名或原来的对象加密算法。定时选择仍由本地加密队列持有，不提前上传媒体。

预览只读取用户明确选择的来源，不写应用拥有的明文临时文件。图片按像素预算生成缩略图，文件超过 100 MiB 或已报告读取错误时无法确认发送。Android 对详情可读但长度未知的文档，在真正导入时强制总量上限。Windows 使用现有有界图片解码器，Mac 使用 ImageIO 缩略图。详情和预览不解锁根身份、不读取聊天资料库。

Android 的确认对象分别持有界面、预览和导入操作的文档/剪贴板授权，最后一个所有者结束后才释放原授权。Mac 的 security-scoped URL 同样由引用所有者保留，发送回调完成后再结束最后一次访问。界面关闭不会让仍在读文件的预览或导入失去授权。Windows 的剪贴板字节继续由原调用方保留，确认/发送结束后执行原来的内存清理；没有新增磁盘中间文件。

桌面说明输入保留 Enter 发送、Shift+Enter 换行；Windows 使用输入法组合状态，Mac 复用现有原生文本编辑桥。真正开始导入后，继续使用[准备进度与取消](V2_PREPARATION.md)及[发送队列](V2_SEND_QUEUE.md)，不把确认界面的临时状态当成已发出或已送达。

安卓图库和文件选择、Windows 和 Mac 文件选择、拖放及剪贴板文件可一次选择最多 10 项。确认界面显示收件人和文件信息，可以添加、移除和调整顺序。说明区可以切换到任何附件，说明跟随该项排序。原位替换附件保留其说明，移除附件也移除该项说明。相册首项的说明按整组显示，其余说明跟随对应项目。回复仍属于首项，按文件发送、静音和定时设置用于整批。录音继续使用发送确认。

多项附件可以用上下按钮排序。安卓长按排序手柄后拖动，双列相册可跨列和跨行拖动，两个桌面端使用鼠标拖动手柄。松手后采用列表的新顺序，图片裁剪和视频剪辑跟随对应附件。三端确认页的缩略图随排序更新发送序号，按文件发送时也显示。安卓读屏可读出当前位置和总数，有预览的视频另有播放图标。

点选可编辑的图片或视频预览，可直接打开该附件的照片编辑或视频剪辑窗口。返回后保留说明、发送选项和其它附件的编辑结果。仍可使用附件下方的编辑和撤销操作。

安卓确认页可继续从系统照片选择器添加照片和视频。已有附件、说明和发送选项会保留。三端退出确认前会询问是否放弃对说明、附件选择和顺序、媒体编辑或发送选项的修改。

安卓附件面板的图库或音频读取失败时保留选择，提供重试。读取成功后才移除已不可访问的项目并恢复图库滚动位置。Windows 确认页在后台读取追加文件时立即显示对应的加载行。Mac 在处理拖入文件时显示进度，并在发送准备或确认弹窗期间暂停接收新的拖入和排序操作。

三端在生成预览前尝试打开附件，将无法读取或超限的文件留在原位置并显示错误。可以重试单项、用系统选择器在原位替换单项，或移除全部不可用项。替换保留其余附件的顺序、编辑结果、说明和发送选项。取消选择器会保留原来的附件，选到批次中已有的文件会提示。确认仍要求当前列表中的所有附件均可用。

Windows 和 Mac 在可发送的聊天区显示媒体和文件两个拖入区域，随指针高亮当前区域，遮罩覆盖期间暂停聊天已读。区域和高亮按系统动画设置淡入淡出。松开后进入同一个发送确认界面，并按所选区域预设「按文件发送」，确认前可以更改。拖入时捕获当前会话及回复草稿，选择器或导入准备期间的新输入继续保留。若有多个文件夹，按拖入顺序逐个打开系统文件选择器。取消某个选择器只跳过该文件夹。用户选定的文件与直接拖入的文件一起进入发送确认。

两个桌面端打开拖入的文件期间显示进度提示，暂停底层聊天已读和活动状态，并忽略重复拖入。切换会话后丢弃旧操作的结果。文件已移动或无法读取时显示错误，原草稿继续保留。读取成功后仍由用户在附件确认界面决定是否发送。

Mac 和 Windows 的附件确认窗口打开时聚焦说明输入框。Tab 在控件之间移动，Enter 确认，Shift＋Enter 换行。返回发送选项或放弃确认后，可继续编辑说明。关闭附件确认会把焦点交回原会话的可用输入框。

整批逐项准备加密对象，进度显示当前附件的文件名、序号及字节进度。全部准备成功后在同一个数据库事务内写入消息或定时队列，并提交媒体所有权和草稿变更。准备失败或取消时逐个释放已暂存对象，并回到确认页的编辑状态。事务保证本地入队的完整性，独立附件仍各自传输和重试。

安卓和 Mac 的附件确认以及 Windows 的文件批次和语音确认会保留到本地入队完成。准备期间可在确认窗口内查看进度并取消。取消或失败后返回同一份附件选择，保留顺序、说明、编辑和发送选项。Windows 语音确认保留加密录音，直到关闭确认且当前发送任务释放录音。

Windows 在重新读取同一路径的视频时保留原剪辑和静音设置。换成其他文件时沿用原槽位的说明，剪辑需要按新视频重新设置。

安卓把准备进度显示在附件确认上方，期间保留原附件列表和说明编辑框。返回键操作当前进度窗口。取消或失败后关闭进度窗口，回到之前的附件列表和编辑位置。

准备失败后，三端重新检查需要读取的原始文件是否还能打开、是否超过大小上限。确认已不可用的条目会显示错误和单项恢复操作。其余项目沿用已有预览，照片编辑已生成的内存来源继续保留。

确认窗口显示重新检查的进度，在文件可用时启用「重试发送」。重试仍使用当前确认页里的附件、顺序、说明、编辑和发送选项。安卓空间不足时将确认按钮换到下一行，取消与重试始终在同一组。

确认窗口按本次发送分配的任务 ID 显示进度并发出取消请求。同一会话还有其他准备任务时，各自的进度和取消操作仍独立。

三端的语音确认可手动试听加密录音。开始准备时释放播放器，取消或失败后恢复试听控件，关闭窗口时结束播放。

两张以上照片或视频可选“发送为相册”，默认选中。切换为按文件发送或混入其他文件时，整批按独立消息发送。相册编号、顺序、数量和各项说明位于 Signal 加密正文。聊天将已加载的成员按顺序显示在同一网格内，支持逐项预览、下载、重试和选择。撤回的成员从网格移出。已读仍由实际进入可见范围的成员触发。

三端从聊天打开相册后可点底部缩略图直接切换成员，当前项有选中标记。聊天照片、相册缩略图和共享媒体可复用独立加密对象库内的派生缩略图。缓存未命中或无法解码时，通过原加密对象生成。原件未下载或仍无法解码时显示占位。关闭预览和定位原消息继续使用现有流程。

SQLCipher 按原对象和尺寸记录最多 192 个缩略图引用，每项编码后最多 128 KiB，再按普通对象分块加密。透明图片保留透明通道，视频缓存静态帧。生成失败或体积超限时保留现有预览路径。删除原对象或移除其本机缓存时移除对应引用，文件经既有垃圾队列回收。接收附件的储存用量和自动下载预算计入对应缩略图的密文字节。全尺寸查看、实际播放及导出沿用原对象。退出或重置身份时先停止接收新的缩略图任务，再等已开始的任务结束。

三端从聊天、共享媒体或收藏另存文件时，选定目标位置后显示写入进度，可在提交前取消。安卓由当前页面持有系统文件选择和写入任务，取消或失败沿用系统文档的清理路径。Mac 和 Windows 在同目录写入临时文件，成功后再提交目标文件。锁定或退出桌面端时取消活动导出，退出等待写入和清理完成。保存前后仍核对原消息或收藏的导出权限。

安卓相册沿用横向分页。Mac 和 Windows 切换到相册中的静态照片时，照片解码完成后从对应方向短距离滑入，工具栏和背景保持固定。关闭系统动画或启用减少动态效果时直接显示。Windows 在鼠标指向底部缩略图条时可用滚轮横向浏览。

两个桌面端的共享媒体浏览使用聊天内已有的静态照片展开与返回动画。缩略图仍在可见区域且来源匹配时，照片从该位置展开并收回。查找不到有效来源时直接进入或退出预览。浏览列表在预览期间保留滚动位置并暂停交互。

相册预览可对当前未下载的收到项请求下载、暂停、继续或重试，沿用现有持久化下载队列。下载完成后原地加载内容，保持当前相册位置。自动下载设置仍生效，浏览缩略图不会主动请求下载。

相册需要收发双方使用包含相册字段的新版客户端。发送非首项说明时，收件端还需使用支持相册逐项说明的共享核心。

从聊天中的相册缩略图打开查看器时，以点中的附件为起点，按已加载的相册顺序切换。安卓支持横向滑动和按钮，放大图片后拖动用于平移。两个桌面端提供前后按钮和方向键，Windows 播放器获得焦点时方向键仍可用于原生播放控制。三端显示当前位置和数量，切换时停止上一项播放。被撤回或过期的附件退出预览范围，点图片本身可继续浏览或缩放。

默认发送原图。用户选中压缩图片时，客户端尝试缩小不超过 32 MiB、6400 万像素的 JPEG 和静态 PNG。压缩图最长边为 2048 像素，JPEG 质量为 82%，PNG 保留透明通道。结果只有比原文件小才采用，动画及其他格式使用原文件。按文件发送保留原始字节。

压缩使用各平台的图像编解码器，输出在内存中交给加密导入。图片来源、发送队列、取消和暂存清理沿用原附件流程。

视频也有独立的压缩选项，默认保留原视频。转码目标为 MP4、H.264 和 AAC，视频最长边不超过 1280 像素。输入最多 100 MiB、10 分钟，输出必须小于输入。压缩不适用时使用原件。当前 Windows 对带方向标记的视频保留原件，Mac 和安卓在转码链路中处理方向。含多音轨或字幕的复杂输入仍保留原件。

Windows 的 MediaTranscoder 写入加密流，Mac 的 AVFoundation 将 MP4 分片写入加密暂存，安卓的 Media3 通过 MediaMuxer 写入加密文件描述符。完成转码后逐块生成可发送对象。取消时等编码器和输出释放，再清理暂存。

三端的发送确认支持旋转和裁剪静态 JPEG／PNG。可编辑的视频可选起止点、预览选段并移除音轨。移除音轨也可以用于完整视频，预览和最终导出都应用此选择。确认界面会标记已移除音轨，并允许撤销编辑。编辑导出失败时，该批次不会入队，原视频也不会自动发送。[Android Media3 转换文档](https://developer.android.com/media/media3/transformer/transformations) [Windows 转码文档](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/transcode-media-files)

照片编辑可水平翻转、锁定原始比例或常用横竖比例，也可切换回自由裁剪。拖动角点保持比例，拖动选区内部移动整块选区。旋转或翻转保留对应的选区，再次打开当前附件时恢复已应用的编辑。每次确认都从原图生成结果。取消继续使用先前结果，应用重置后恢复原图。照片编辑沿用内存输出和附件发送确认。 [Telegram Android 比例选择](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/Components/Crop/CropView.java#L1296-L1355) [Telegram Desktop 翻转与比例](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/editor/photo_editor_controls.cpp#L856-L912) [WPF 图像旋转与翻转](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/Media/Imaging/TransformedBitmap.cs#L79-L138)

视频确认的缩略图时间轴可以直接拖动起点或终点。拖动会暂停选段预览并更新时间，松手时跳到相应位置。保留原生滑块供键盘和辅助功能调节。Windows 从用户已选文件取最多六帧放在内存，取帧超时或失败时仍可使用时间轴和滑块。 [Windows MediaComposition 取帧 API](https://learn.microsoft.com/en-us/uwp/api/windows.media.editing.mediacomposition.getthumbnailasync?view=winrt-26100)
