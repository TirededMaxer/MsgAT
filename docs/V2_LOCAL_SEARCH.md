# V2 本地消息搜索

状态：实现进行中；2026-11-09 按用户要求停止分阶段测试，先完成全部代码，再统一构建和实际验收。

## 数据与加密

搜索完全在客户端进行，不向服务端提交关键词、结果或聊天正文。根种子和现有密钥层级保持不变。FTS5 trigram 索引与消息一起保存在原有 SQLCipher 加密库中，首次搜索时在后台事务内初始化；不会创建明文搜索数据库或索引文件。三端设置 `temp_store=MEMORY`，避免 SQLite 临时排序写出明文文件。

三端共同打包 [共享 SQL](../shared/storage/message-search.sql)，避免各端自行维护不同的索引规则。索引内容包括未撤回的文字消息，以及附件的文件名和说明文字，不包含未发送草稿。联系人名称来自查询时的会话表，修改名称不需要复制或重建消息索引。

持久数据库触发器处理新增、编辑、撤回、删除、附件说明和元信息变更。修改与索引更新共用应用原本的数据库事务；清历史、删联系人和身份销毁走既有数据生命周期。FTS 索引属于可重建的加密派生数据，不是独立身份或消息真相来源。

三端查询时跳过已到期的消息，即使后台清理还未删除索引记录。打开结果前再次确认它仍属于原会话、未撤回且未到期。

## 查询与交互

- 支持当前会话与全部会话范围，以及全部、文字、附件三种类型筛选。文字和中文子串按字面搜索。三个及以上 Unicode 标量使用 trigram 索引，更短的查询在加密库内扫描匹配。类型筛选与会话和分页条件一起执行。
- 搜索词可与日期筛选组合。查询按本机时区的当天起点和次日起点限制结果。切回搜索列表、刷新、翻页和在聊天里前后跳转都沿用选定日期。
- SQL 使用参数，FTS 查询使用转义后的引号短语，输入不会被解释成 FTS 搜索操作符。查询最多 256 个 Unicode 标量，拒绝 NUL；不在日志中输出关键词或结果。
- 每页 50 条，以消息时间和 ID 双字段排序及分页，避免相同时间下遗漏结果。结果摘要有长度上限；界面有输入防抖、加载、空结果和失败状态，过期查询不得覆盖新查询。
- 安卓使用 Compose 搜索对话框，Mac 使用 SwiftUI sheet，Windows 使用 WPF 对话框和 Ctrl+F。桌面打开搜索后聚焦输入框，方向键移动结果选中项，按到已加载结果末尾可加载下一页。回车打开选中结果，Escape 关闭。输入法组合期间保留系统按键处理。打开前仍会核对消息所属会话和撤回状态。
- 消息定位从目标附近加载历史窗口，保留向更早/更新消息翻页及返回最新消息的路径，避免为了旧消息加载整个聊天。浏览历史窗口时不得把窗口底部误认成聊天最新位置并发送已读。

结果行对齐会话名称和本地时间，并标记附件结果。客户端分别记住全局入口和各会话入口最近一次的搜索，最多保留 16 个入口。重新打开时恢复关键词、筛选和选中结果，再从加密库查询。搜索状态只在进程内保留，应用锁定时清除。

从搜索结果打开旧消息后，聊天区顶部显示搜索词。点击搜索词可恢复原来的全局或会话搜索范围、筛选和已加载的结果。所选消息仍有效时，结果列表定位到该条。关闭导航条会保留当前历史定位和已记住的搜索条件。切换会话后清除导航条。安卓打开当前会话里的搜索结果时沿用当前聊天页面及其草稿。

打开当前会话的结果时保留正在编辑的消息。跨会话打开结果前，若有未保存的编辑，先请用户确认。选择保留编辑时仍可从原关键词、筛选和选中行继续搜索。确认离开后再检查目标消息是否仍可打开。

搜索结果底部提供上一条、下一条和当前选中位置。位置指已加载结果中的序号。在最后一条继续向下时，客户端加载下一页并选中第一条新增结果。确认后打开选中的消息。

从单个会话的搜索结果进入聊天后，可在聊天内直接跳到上一条或下一条匹配消息。沿用原搜索词和类型筛选，按时间及消息 ID 定位。返回结果列表时恢复最近一次跳到的消息。只有跳到已加载范围之外时才增加恢复条数。

macOS 用 Cmd+G、Shift+Cmd+G 跳到下一条和上一条结果。Windows 对应 F3、Shift+F3。Escape 优先处理当前浮层、编辑、选择或回复，之后才收起搜索导航。输入法的组合文字由原生编辑器处理。

关键词和筛选不变时，数据库通知会合并后刷新已经加载的结果范围，继续保留分页入口。通知到达时若查询正在进行，当前查询先完成，随后再处理待刷新状态。桌面保留仍在结果范围内的选中消息，Windows 就地更新结果行。改变关键词或筛选时重新从第一页开始。

三端查询失败时保留当前关键词、筛选和已加载结果。重试会重新执行失败的查询或分页，仍按当前条件读取本机加密库。

若按「下一条」触发的翻页失败，重试成功后会从原选中结果继续定位。手动移开选择后，重试只加载结果。等待重试时收到数据库刷新通知，会在分页恢复后再刷新结果。

## 已获得证据与剩余条件

用户停止测试前，三端第一版搜索实现通过编译，安卓 lint 通过，安卓和 Mac 包内共享 SQL 与当时源码哈希一致。Mac 隔离客户端实际搜索 `V2` 返回四条已存在消息；搜索 `端到端` 返回对应中文消息，分别覆盖短文本扫描和 trigram 分支。它没有连接测试中继，搜索不依赖网络。

Mac 结果行的自动化点击只聚焦了列表，尚未证明跳转；源码随后增加了明确的选择/Open 入口。后续桌面历史窗口、分页和已读边界修改均在用户停止测试后编写，尚未构建或实际验收。最新共享 SQL 增加了历史定位索引，其哈希也已不同于先前验收包。

统一验收必须覆盖三端搜索范围、中文/英文/短词/引号、文件名和说明、超过一页与相同时间的结果、编辑/撤回/删除后的同步、结果失效、重开索引、历史双向加载及已读边界，并核对大量历史下的实际占用和响应。当前证据不代表这些条件已全部满足。
