# 服务端部署

## 启动

安装 Java 21，将 Release 中的 `MsgAT-Console-1.1.jar` 放入服务目录：

```bash
java -jar MsgAT-Console-1.1.jar
```

监听端口从 **JAR 所在目录** 的 `server-config.json` 读取，与运行命令时的当前目录无关。文件缺失时，首次启动自动创建：

```json
{
  "port": 34478
}
```

修改 `port` 后重启服务端生效，取值必须是 1–65535 的整数；省略该字段时默认 34478。JSON 格式错误、重复字段、未知字段或非法端口会明确报错并停止启动，不会悄悄改用其他端口。目录需要允许首次创建配置文件；已经存在的配置不会被覆盖。旧的命令行端口参数已改为此 JSON 配置，请移除启动命令末尾的端口参数。部署时同步修改防火墙放行端口。

程序在当前目录创建 `data/`，保存用户资料和离线包。升级时先停止旧进程、备份并保留数据目录，再更换 JAR。不要同时运行多个进程访问同一数据库。原程序内置数据库密钥已恢复，本版无需 `MSGAT_DATABASE_KEY` 或额外数据库密钥文件；混淆 JAR 支持正常 JVM 校验，无需 `-noverify`。

## TLS

默认自动生成临时自签名证书。三端客户端默认允许不受信任的证书，后端重启无需手动更新指纹。

若需要固定证书，可同时设置：

```bash
export MSGAT_TLS_CERT=/path/to/fullchain.pem
export MSGAT_TLS_KEY=/path/to/privkey.pem
java -jar MsgAT-Console-1.1.jar
```

只配置其中一个变量会导致启动失败。客户端填写指纹时，指纹必须与服务端实际证书匹配。未填写指纹并关闭兼容选项时，使用系统证书校验。

## 持久运行和网络

建议用操作系统服务管理器设置工作目录、自动重启和日志。程序的数据目录与当前工作目录有关，也可用 `-Dmsgat.data.dir=/path/to/data` 显式指定，参数放在 `-jar` 前。

服务端仅承担聊天和通话信令中继。语音媒体通过 WebRTC 连接，跨 NAT 或严格防火墙环境可能需要独立 TURN 服务及相应网络规则。

正常关闭和重启保留离线消息。`MSGAT_ENABLE_KILL_SWITCH` 默认不启用；不要在普通部署中开启，该功能包含破坏性清理逻辑。安全边界见 [SECURITY.md](../SECURITY.md)。


## 资源与吞吐复核（2026-10-04）

本轮执行源码复核和 Release 构建，按用户要求未运行客户端测试、服务端压测或生产监控。因此没有实测 RSS、CPU 百分比或并发容量数据；以下为代码中的约束与优化，不代表测得的性能提升。

| 项目 | 原问题 | 本版处理 |
| --- | --- | --- |
| 离线同步内存 | 一次加载整个收件箱，最多 256 MiB 存储数据，另有解密和编码副本 | 按 ID 每批读取最多 8 个包，批量 flush，写出后继续；同步期间的新持久消息由后续批次顺序补齐 |
| 慢连接 | 不断向网络队列追加包 | 每连接待写包按线格式大小计数，最多 4 MiB（不包含 TLS、套接字和对象开销）；超限关闭连接，已入库消息留待重连，实时语音信令不入库 |
| 网络线程 | 数据库锁和磁盘等待直接阻塞网络循环 | 使用 2–4 个独立有序业务线程，同连接保持顺序；每线程队列最多 64 个任务，饱和关闭来源连接；每连接积压达到 8 个包时暂停读取，降至 4 个时恢复 |
| 线程数量 | 网络线程默认随 CPU 数量放大 | 接收线程 1 个，网络工作线程 2–8 个，业务线程 2–4 个；按 CPU 数量取范围内的值 |
| 分片入库 | 每个包重新 SUM 整个收件箱，随着附件增长重复扫描 | 增量配额表与消息插入、更新、删除在同一数据库事务中维护；旧数据库首次启动时回填一次；ACK、过期清理、账户删除都会更新计数 |
| 过期消息 | 单次大批删除长期占用写锁 | 每次最多删除 1000 条，分批提交，可在关闭时停止 |
| 编码与日志 | 小包生成约 4 KiB 临时填充数组、默认日志偏多 | 直接向 ByteBuf 写入随机填充，减少临时数组；默认 INFO 日志 |

保留 4 KiB 最小填充、256 KiB 帧上限、TCP_NODELAY、TLS、按确认删除和 3 天离线保留策略。没有为降低开销关闭持久化或更换数据库密钥。SQLite 仍采用回滚日志以保留跨两个数据库文件删除账户时的原子性；磁盘同步、写入串行化及高并发下的吞吐上限仍需结合实际服务器负载评估。

业务线程队列使用 Netty 的 [DefaultEventExecutorGroup](https://netty.io/4.2/api/io/netty/util/concurrent/DefaultEventExecutorGroup.html) 有界任务队列。安装包校验信息见下载目录中的 `SHA256SUMS.txt` 和 `release-manifest.json`。
