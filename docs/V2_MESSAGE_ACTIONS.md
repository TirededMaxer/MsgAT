# V2 转发、多选与本地收藏

状态：2026-11-09，数据层、协议协调器和三端必要操作入口已接入源码。按用户最新要求，本轮不构建、不安装、不运行客户端测试，不能把源码状态当作功能验收完成；这些入口也不代表 Telegram 参考 UI 重构完成。

## 数据与加密

- `message_forwards` 保存转发显示名与原消息日期，与新消息同事务提交。显示名只是转发内容中的说明，不是经过原作者认证的签名，不显示原作者的身份验证标记。
- `saved_messages` 是现有 SQLCipher 库内的独立快照，包括正文/说明、原位置线索、显示名、保存日期及加密对象引用。它不依赖原消息外键，原消息编辑、撤回或清历史后，已经成功收藏的副本继续存在。
- 文件转发和收藏使用共享 Rust 核心的 `rekey_object_file`：读取已下载的加密对象，逐块认证、解密并立即以新对象 ID、新内容密钥和新下载凭据重新加密。正文块使用清理内存的缓冲区，不创建明文临时文件；核对原对象和明文摘要，失败时移除新副本。
- 内容密钥继续通过当前根种子与新对象上下文派生，根身份及硬件封装不变。新副本的密钥和凭据进入当前 SQLCipher 库；转发时只通过对应收件人的 Signal 会话传递。不同收件人使用不同的加密对象副本，不复用原下载凭据。
- 隐藏发送者时移除转发署名；隐藏说明时移除附件说明。原会话 ID、原消息 ID、旧下载凭据和旧内容密钥不进入新的转发载荷；原消息的回复上下文不会作为可跳转的引用带入另一会话。

## 提交和生命周期

准备副本前读取当前数据，提交前再次核对原消息存在、未撤回、正文/附件未变，以及所有收件人仍为已同意且未拉黑的联系人。任何一项失效，整批本地消息和发送队列回滚，未提交的新对象被清理。每批最多 100 条消息、20 位收件人，使用新消息 ID 和统一批次时间；批内 ID 按顺序分配，保持原消息的时间顺序。

三端在读取来源和提交副本时都检查本机历史保留期限。已经超过保留期限、仍待后台清理的消息无法转发或新建收藏。已收藏的副本可以继续打开和转发。

转发现在先建立 SQLCipher 持久任务，附件未下载时等待原有传输完成；不会转发缺失对象或退回旧下载凭据。三端新增任务状态、失败重试、取消和重启恢复的源码，见[持久转发任务](V2_FORWARD_TASKS.md)。本地收藏仍要求附件完整下载后再创建独立快照。

成功提交的转发进入既有持久队列，由正常重连/重试路径发送，不修改输入区草稿。收藏不需要网络；删除收藏只清理没有其他消息、传输或收藏引用的对象。清历史和撤回清理保留仍被收藏引用的对象。

Windows 跟踪并等待消息操作与导入任务；Android 的消息、附件及收藏协程在身份销毁前取消并等待结束；Mac 先停止接纳协议操作，再等待导入及完成回调，收藏队列也在销毁身份前结束。取消发生在数据库提交边界时，不得把已经提交的文件作为失败副本删除。

## 操作入口

三端的转发署名跟随界面语言。文字消息在气泡内显示来源，媒体和文件在内容上方显示来源；普通连续消息的分组在转发消息处断开。接收端只显示加密正文中提供的署名，选择隐藏署名时不会从当前联系人推断原作者。

三端支持从消息菜单进入多选、转发和收藏。选择数量限制为 100，转发面板可搜索并选择最多 20 位联系人，确认前可隐藏署名或媒体说明。选择模式停用输入区并保留原草稿；成功保存或转发后，只有仍匹配提交快照的选择才会清空。重复点击不启动重复的同一面板提交。

转发确认保留跨搜索的收件人选择，按选择顺序显示可移除的头像标签。Android 使用底部面板和头像网格，Windows 使用可键盘操作的头像网格，Mac 使用原生列表。底部保留转发按钮、收件人数及独立选项菜单。联系人载入失败时可重试，入队失败时保留选择和选项。成功提示为「已加入转发队列」，具体送达状态在目标聊天中查看。 [Telegram Android 头像网格](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/Components/ShareAlert.java#L1095-L1111) [Telegram 原生 Mac 收件人列表](https://github.com/TelegramMessenger/telegram-macos/blob/561169337e838c3281f7cfe24652757a5b522df9/packages/ShareUI/Sources/ShareUI/ShareModalController.swift#L54-L74) [Telegram Desktop 收件人标签](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/boxes/share_box.cpp#L620-L647)

三端的消息菜单和多选工具栏提供本机删除。确认后按当前会话和最多 100 个消息 ID 在一个事务内删除，清掉同会话引用中的原文摘录，并使用现有索引、附件引用和垃圾回收规则更新本机资料库。待发消息走发送队列的取消流程。聊天内单条删除不适用于实时位置。删除使用本机事务，不生成对端撤回事件。

三端多选删除确认也可选择为双方撤回。只有已知都是本人发出、已获中继确认且仍可撤回的消息时才显示选项。确认后逐条检查会话、作者、当前状态和到期时间，在同一事务中写入本机撤回状态及各自的加密撤回事件。任何一项失效时整批回滚并保留选择。撤回通过现有发送队列送达对端，支持离线排队。

打开删除确认时，从加密资料库读取所有选中消息的状态。跨历史分页选中的消息即使已经滚出当前加载范围，仍可参加同一批删除或撤回。切换聊天或更改选择后丢弃旧查询结果。

主菜单的收藏入口提供 50 条分页、文字查看/复制、媒体查看/显式导出、多选转发、删除确认和原消息定位。媒体说明从收藏快照读取；原位置失效时显示提示，不删除收藏。Windows 与 Mac 继续使用原生窗口和现有双栏结构。Android 小窗口操作区可换行；Mac 收藏媒体仍走加密资源读取。

收藏可以按保存时间或来源聊天浏览。进入某个聊天后，搜索只查该来源；在收藏首页输入时查整个收藏库。关键词匹配作者、附件名称及可见的正文或说明，隐藏片段不会命中。查询按保存时间和 ID 分批读取加密库，筛选结果仍以每页 50 条展示。原聊天被删除后，收藏按原来源 ID 归组，副本继续可读。 [Telegram 收藏视图参考](https://telegram.org/blog/new-saved-messages-and-9-more#saved-messages-2-0)

三端收藏支持手动刷新。读取失败时保留已显示的结果，重试同一次读取；删除已确认的收藏后，只从当前列表移除对应项目，保留搜索和分页。收藏正文详情显示保存时的链接预览。

收藏媒体预览有「保存附件」和「在聊天中显示」。保存前及完成导出前都校验收藏仍引用该可用对象。定位前核对收藏及原消息仍在对应聊天，失效时保留当前列表或预览。三端继续使用现有的加密对象和独立收藏引用，按来源浏览只新增加密库内的普通索引。
