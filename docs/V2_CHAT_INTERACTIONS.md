# 完整聊天交互范围

2026-11-10 用户再次明确：聊天功能包含加号菜单、拍照、拍视频等完整入口，以及 Telegram 发送文件二次确认等细节；这些只是例子，需要覆盖相同流程中的关联行为。不能把“能选一张图片并发出去”作为整个附件模块完成的依据。

本文件是编写范围，不是验收结果。当前继续完成底层功能及现有界面中的必要入口；充分完成官方包/源码与 Chrome 静音 YouTube 参考研究后，才集中重构最终原生 UI、布局与动画。

## 输入与加号菜单

三端共用网址识别。正文和附件说明中的 HTTP(S) 链接识别大小写不同的协议前缀，`www.` 开头的常规网址使用 HTTPS。全角句号、逗号和右括号等结尾标点留在链接之外。预览候选和共享链接沿用相同规则。

桌面端链接使用系统默认浏览器。Windows 在链接和预览卡片上显示实际地址，右键可打开或复制。Mac 在带链接的文本段落和预览卡片悬停时显示地址，右键按地址选择打开或复制。安卓长按链接或预览卡片可查看完整地址、打开或复制。剧透内的链接在揭开前不出现在菜单或悬停提示中。

三端均覆盖文本/引用/编辑状态切换、光标与选区保留、输入法组合输入、草稿恢复、格式操作、发送中/失败/重试、定时/静默发送，以及输入、录制与通话状态的即时刷新。移动端需处理键盘、系统 Insets、安全区域、旋转和返回手势；桌面需处理焦点、鼠标、窗口尺寸、Enter 发送、Shift+Enter 换行、常用快捷键、拖放与剪贴板粘贴。

三端设置中的聊天字号提供 85%、100%、115% 和 130% 四档，默认 100%。调整后，消息正文、媒体说明和输入框立即使用新字号。比例保存在本机，已有消息、草稿和会话列表无需迁移。

三端设置均提供跟随系统、浅色和深色，默认跟随系统。选项保存在本机。Android 使用 Compose 配色，Mac 使用 SwiftUI 原生外观并调整聊天气泡，Windows 使用 WPF 配色并同步标题栏。独立媒体播放界面仍使用深色背景。[Microsoft Windows 应用主题文档](https://learn.microsoft.com/windows/apps/desktop/modernize/ui/apply-windows-themes)

三端设置提供跟随系统、英语和简体中文，默认跟随系统。设置、会话列表、聊天主界面、附件发送确认、照片和视频编辑、定时发送选项及系统消息与来电通知已接入本地语言资源。隐私设置、应用锁、身份重置确认、消息保留和附件缓存也使用所选语言。通知只翻译客户端生成的提示，发送方名称和预览正文保持原样。部分高级对话框和错误仍有英语文案。

Windows 设置可以决定点主窗口关闭按钮时留在系统托盘，还是完全退出。升级默认保留托盘行为。如果托盘图标暂时无法注册，窗口最小化到任务栏，方便重新打开。关闭开关后，关闭按钮与托盘「退出」共用退出流程，先收尾通话、发送队列和加密库。托盘菜单随界面语言切换。实际关闭、恢复和退出留到统一实机验收。

Windows 启动时显示打开进度，随后保留双栏框架并从后台读取会话、文件夹和好友申请。首次读取失败时，会话栏提供重试。读取期间产生的消息变化在列表就绪后更新；从通知打开的目标也等列表就绪后再定位。

点击 Windows 消息通知时，应用锁或覆盖聊天的通话界面消失后才定位。进入其他会话前沿用放弃未保存编辑的确认。目标必须仍在本机历史中，置顶通知还要求对方的置顶仍然有效。定位完成后按实际可见区域计算已读。应用处于锁定页时仍可发出通用通知，通知内容不含联系人或正文。

安卓和 Mac 在聊天内打开通知时，先等待通话、媒体等覆盖界面退出。同一会话直接定位并保留编辑状态，切到其他会话前沿用放弃未保存编辑的确认。确认后重新核对通知凭据与消息是否仍有效，过期或失效时提示用户。

安卓和 Mac 替换同一会话的通知时，也更换定位凭据。旧通知的点击不会改指新消息。置顶通知只有在对方的置顶仍有效时才打开。升级时旧版本的通知定位凭据一次性失效，聊天历史照常保留。

三端的通知设置提供系统入口。安卓在返回时刷新应用通知是否被系统关闭。macOS 重新激活时刷新授权和预览选项，仍仅在系统为解锁后预览时提交短正文。Windows 使用系统通知页管理系统层开关。 [Android 应用通知设置](https://developer.android.com/reference/android/provider/Settings#ACTION_APP_NOTIFICATION_SETTINGS) · [Apple 通知设置](https://support.apple.com/en-ca/guide/mac-help/-mh40583/mac) · [Windows 设置入口](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings#system)

设置首页支持按当前界面语言的名称和相关词查找。安卓从顶栏搜索图标打开，两个桌面端在首页显示搜索框。搜索结果沿用原来的设置控件和子页。选择高级网络会展开 TURN 和证书设置，返回首页后保留搜索词。搜索只匹配内置名称和关键词，不读取账号、服务器地址或密码的值。 [Telegram Android 设置搜索](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/SettingsActivity.java#L287-L321) [Telegram Desktop 设置关键词](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/settings/sections/settings_main.cpp#L485-L496)

搜索 TURN 或证书指纹可以直接定位到网络页中对应的部分。返回首页保留未保存的网络编辑。点网络页的「取消」恢复进入设置时的配置并返回首页，搜索词仍保留。

设置中的通知页提供全局消息提醒和声音开关。关闭提醒时继续收消息及更新未读数。关闭声音保留可见提醒，会话静音和发件人的无声发送仍按原规则处理。来电通过独立的来电提醒路径。Android 和 Mac 的预览开关移到通知页，保留原偏好，并对正文中的剧透使用占位内容。Windows 托盘通知使用通用提示。新增偏好存放于现有加密库，升级默认开启消息提醒及声音。

回复和编辑的提示条都可定位原消息。编辑使用独立的输入状态，原草稿、回复和发送选项继续保留。修改成功或取消后回到原输入框，提交失败时保留待编辑文本。桌面编辑时保留 Enter 保存、Shift+Enter 换行和输入法组合状态。编辑目标撤回或过期时退出编辑。

保存编辑期间，输入框保留文本并暂时只读。恢复输入焦点前检查当前会话和前台状态。Windows 普通发送完成后，只在发送成功且仍停留在原会话的最新消息处时跟随消息，避免从正在阅读的旧消息突然跳走。

三端输入格式菜单跟随界面语言。桌面右键菜单显示各格式的快捷键，Windows 初次打开时即使用客户端菜单，Mac 保留系统文字编辑命令。输入法组字或输入框只读时停用格式操作。

安卓连接实体键盘时，Enter 发送消息或保存编辑，Shift＋Enter 换行。输入法组字时仍由输入法处理。发送完成后按正文、回复目标和引用文字判断是否清空草稿，送达状态更新不影响此判断。

安卓实体键盘在空输入框按 ↑ 可定位最近一条可编辑的己方消息。Ctrl＋↑／↓ 切换回复目标并保留已有草稿，越过最后一条时结束回复。Escape 可取消回复，编辑有改动时沿用放弃确认。读取结果只在输入框仍聚焦、当前回复和会话未变化时应用。

三端在当前文字消息写入本地发送队列期间暂停再次提交，输入框仍可编辑。提交失败时保留输入，成功时只清除与本次发送匹配的草稿。

桌面输入框获得焦点且没有草稿或引用时，按 ↑ 从当前会话查找最近可编辑的己方消息，定位到原消息并将焦点交给编辑框。翻阅历史时也可使用，跳转沿用已有的历史返回位置。Mac 的 Cmd＋↑／↓ 在空输入框中切换回复目标，Windows 用 Ctrl＋↑／↓ 并保留已有草稿。编辑和回复快捷键都跳过已撤回或已经超出本机保留期限的消息。继续向下越过最后一条或按 Escape 会取消回复，保留草稿。输入法组合期间交还系统处理。 [Telegram Mac 快捷键](https://github.com/overtake/TelegramSwift/blob/561169337e838c3281f7cfe24652757a5b522df9/packages/ChatUI/Sources/ChatUI/ChatController.swift#L10908-L10999) [Telegram Desktop 快捷键](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/history/history_widget.cpp#L9479-L9513)

三端回复和编辑共用输入框上方的位置，以独立图标区分，支持点击摘要定位和单独取消。当前加载的回复目标被编辑时，摘要随消息刷新。文字、关闭按钮和定位动作接入中英文。安卓栏跟随输入区展开和收起，参考源码使用 250 ms 与聊天列表的缓动曲线。Mac 支持减少动态效果，Windows 使用原生控件并扩大关闭按钮。动效和焦点留待统一客户端验收。 [Telegram Android 输入区](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/Components/ChatActivityEnterView.java#L15861-L15921) [动画参数](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/recyclerview/ChatListItemAnimator.java#L47-L48)

回复摘要跟随原消息更新，即使原消息已离开当前历史分页。附件摘要优先显示说明，其次显示文件名。原消息删除或撤回，或所选文字引用因原文编辑而失效时，清除回复目标并保留输入文字。已经发送的引用保留发送时的片段。

三端单聊的附件菜单支持添加、修改和清空自己发送的文件或媒体说明。编辑事件随原 Signal 会话加密发送，仍按原作者、消息 ID 和修订号归并。图片、视频和文件本体不重新上传。原消息晚于编辑到达时，先校验附件类型再应用缓存中的编辑。贴纸、自毁消息及已经撤回的消息不支持此操作。旧开发版的事件校验器需要升级后才能接收附件说明编辑。

三端从消息引用或输入框引用条跳转成功后，聊天右下角提供返回按钮。连续跳转最多记住 16 个阅读位置，可逐层返回。记录只在当前会话内使用，主动跳到最新消息会清除记录。历史消息已过期或被删除时显示找不到的提示。

历史消息的引用条在正文或附件上方，作者和摘要分行显示。普通文字保留在原气泡内，附件的引用条有独立的点击区域。已有的附件、撤回和预览缺失状态分别显示，点击仍沿用原消息定位。

点击引用时先确认原消息仍在当前会话。原消息已撤回且仍有占位时，可以定位到撤回提示。历史已清除或原消息到期时，显示引用原文不可用的提示并留在当前阅读位置。读取历史失败时显示单独的加载失败提示。

三端可以从普通文字消息的菜单打开「引用所选文字」，在原气泡内用系统选区选字，确认后带回输入框。取消后恢复原气泡和链接。草稿在加密资料库里记录原消息、选区和内容校验值，重开会话时从原消息恢复。发送时在本地事务中重新核对来源，再沿用端到端加密的 `reply` 事件字段发送片段。自毁消息不提供片段引用，剧透以占位文字显示。选区失效时保留输入的草稿。原生选区、焦点和三端互通留待统一验收。

三端在自毁消息的时间旁显示时钟，消息菜单显示本机时区下的到期日期和时间。单条消息的菜单不提供编辑、片段引用、转发、收藏和导出附件。多选包含已加载的自毁消息时禁用转发与收藏。保留普通回复和本机删除操作。聊天历史、日期和未读跳转、搜索、共享媒体和附件导出在查询时也应用本机保留期限。到期的消息即使仍在等待后台清理，也不会从这些入口重新出现。

安卓聊天中，向左滑动消息（从右到左的界面向右滑）会显示回复图标。滑过阈值时有触觉提示，松手后引用该消息并聚焦输入框。短滑或中途取消时，消息回到原位。长按菜单也可发起回复。[Telegram 安卓版手势说明](https://translations.telegram.org/ga/android/unsorted/SwipeToReplyHintMessage)

Mac 和 Windows 可以双击消息旁的留白来回复，聚焦现有输入框并保留草稿。正文、链接、引用和媒体保留各自的点击动作。多选或编辑时沿用相应模式的操作。[Telegram Mac 消息行操作](https://github.com/overtake/TelegramSwift/blob/561169337e838c3281f7cfe24652757a5b522df9/packages/ChatUI/Sources/ChatUI/ChatRowView.swift#L2612-L2634)

聊天顶栏左侧显示圆形头像、会话名称和紧随名称的小号连接标记。副标题平时显示连接状态，有输入等会话活动时显示对应提示。右侧提供语音通话和聊天内搜索。两个桌面端直接显示视频通话，安卓把视频通话放进聊天操作菜单。Windows 保留独立的历史导航图标，会话管理仍通过左侧列表右键访问。选择消息时，顶栏显示选中数量及转发、收藏和取消操作。安卓头像和名称随加密资料库中的联系人更新刷新。

三端通话状态和常用操作使用界面语言。安卓来电、通话和小窗头像沿用加密联系人头像读取。Windows 来电时将键盘焦点移到拒接按钮，通话面板内的 Tab 键在控件间循环。浅色主题下，Windows 的联系资料和通话状态使用主题文字颜色。

安卓在拨打或接听时申请该通话所需的权限。点来电通知的接听按钮会进入前台，启用应用锁时先解锁。权限回调只接听仍在响铃的原来电。

三端在通话结束时短暂显示具体结果，包括未接、拒接、忙线、取消或失败。结果沿用通话记录的判定。安卓在全屏通话界面按返回键可收起到通话小窗。

主叫端发送到聊天里的通话摘要使用同一个结束结果。未接、拒接、忙线、取消和失败分别显示，接通过的通话继续使用时长。同一通话只由主叫端生成摘要。

三端聊天气泡和会话列表会按当前语言显示符合既有格式的通话摘要。原文本仍用于传输、复制和引用，定位文字引用时显示原文以匹配引用片段。

已接通的通话暂时断网时，三端在主界面和小窗显示「正在重新连接」，清除旧的延迟读数。若连接恢复，界面继续显示原通话时长。Windows 每次中断只保留一个恢复期限，恢复后取消该期限。

安卓在系统确认新通话设备后更新选中状态。等待超过五秒则回到系统自动路由。macOS 合并短时间内的设备变化，系统暂时无法提供默认设备时再尝试一次。Windows 检测到系统默认麦克风变更后重新打开该输入，保留静音状态。Windows 输出快捷键在系统默认输出和通信设备之间切换，指定耳机或扬声器可从音频设备菜单选择。

安卓在前台和后台都通过系统来电通知响铃，铃声受来电通知分类设置控制。接听、拒接或超时会清除响铃通知，通话中的通知不再响铃。Windows 在来电期间播放系统提示音，离开响铃状态时停止重复播放。Mac 继续使用系统通知声音，并在所有通话结束路径清理来电通知。

Mac 通知的「接听」操作在前台处理，应用锁启用时先解锁，只能接听仍在响铃的原来电。Windows 点击来电托盘通知后恢复主窗口，解锁后可在来电界面操作。托盘通知沿用通话服务的响铃，避免叠加第二个提示音。

macOS 和 Windows 前台有设置或发送确认窗口时，来电会显示在独立的原生小窗口中。出现时保留原输入焦点，点击来电通知可把焦点移到接听和拒接控件。接通后，小窗口提供静音与挂断，原对话框关闭时恢复主窗口里的通话界面和视频。按钮只作用于当前通话，应用锁或退出会关闭小窗口。原对话框中的说明、选项和草稿由原窗口保留。

三端通话小窗沿用主通话界面的状态，接通后显示时长，静音时显示麦克风图标。小窗可以拖动，点击可恢复主通话界面。

全屏通话覆盖聊天时暂停按可见消息统计已读。安卓同时收起输入法。Mac 和 Windows 收起通话小窗或结束通话时，若原聊天仍可操作，则尝试恢复先前的键盘焦点。Windows 还可用 Escape 收起已接听或拨出的通话。

三端通话记录在新增记录、清空聊天或删除联系人后刷新。刷新时保留已加载的页数，加载旧记录失败时可重试该页。

通话记录使用联系人的当前头像，加入来电和去电方向图标。未接通话的状态使用醒目颜色，时间按客户端语言显示。点击记录进入聊天，单独的按钮用于回拨。

通话记录可切换「全部通话」和「未接来电」。筛选在本机资料库中先于分页执行，所以更早的未接来电也能加载。切换时从所选列表顶部开始。

三端发送端每个会话最多开始一项有效分享。每项分享最多保留一个等待中继确认的加密更新和一个可被更新坐标覆盖的待加密更新。主动停止会清除排队的坐标更新，并排入停止事件。若开始事件仍未加密，则直接取消排队。

三端均有 15 分钟、1 小时、8 小时三个时长，开始前获取设备定位。聊天卡片和详情在更新提交后刷新，可主动停止或打开地图。安卓使用带停止操作的定位前台服务，划掉任务会结束采集。Mac 和 Windows 仅在客户端处于活动状态时采集，退出或身份重置时结束分享。进程重启后不会自动恢复采集。

菜单本身覆盖展开/收起、选中态、点击外部/返回/Escape 关闭、键盘弹出后的布局、滚动与窗口变更、动画中断及反向过渡。语音消息、视频录制和一对一通话是不同功能，分别实现各自生命周期。

## 相机和录制

拍照流程包含权限、预览、前后摄像头切换、可用设备选择、拍摄、重拍、确认和取消；拍摄视频还包含开始、暂停/恢复能力、结束、时长、资源上限、回看和明确发送。语音消息包含按住录制、锁定持续录制、取消、试听、删除、发送及中断恢复。具体按钮、手势和动画以对应平台 Telegram 参考为准。

拍摄/录制结果进入与文件选择相同的发送准备流程，不能拍完直接外发。捕获任务必须持有自己的生命周期与暂存所有权，先登记再创建素材；取消、后台限制、权限撤销、锁屏、中断、切换会话和退出时停止设备并清理未提交结果。音视频编码/封装不能以未经说明的明文公共缓存替代加密暂存设计。

安卓已有独立的拍照和录像界面，拍照后可重拍，录像可暂停、继续和回看，再进入附件确认界面。相机、闪光灯、补光灯和错误提示跟随界面语言。三端均有独立的语音消息录制入口。拍照、录像和录音流程留待统一真机验收。

## 选择与发送确认

Android 系统分享可将带读取授权的文件、图片、音视频或文字带入 MsgAT。解锁后选择已接受且未拉黑的联系人。附件进入原有发送确认，一次最多 10 项，共享文字可填入第一项说明。只分享文字时追加到现有聊天草稿，由用户决定是否发送。符合格式的图片和表情包仍可选择导入贴纸库。分享请求只保存在当前应用会话中，取消不会创建消息或消耗原草稿。

文件选择、图库、相机拍摄、录制结果、桌面剪贴板文件列表和拖入均使用对应的预览和确认流程。Android 从其他应用拖到聊天输入框的图片也先确认。Mac 的 Cmd＋O 和 Windows 的 Ctrl＋O 都可从可发送的聊天打开文件选择器，选中的文件进入现有发送确认。多附件支持排序、增删、按相册或单独发送、说明、压缩、原图、按文件发送和准备进度。剪贴板图片直接入队的范围见 [附件发送确认](V2_MEDIA_CONFIRMATION.md)。

桌面拖放需有进入/悬停/离开反馈，区分素材与文件模式；确认关闭后恢复聊天焦点。输入法未提交的 Enter 不发送，拖放/粘贴不覆盖已有草稿。发送提交后仅清理与该次快照匹配的草稿/回复/选项，避免异步完成覆盖用户新输入。

三端多附件选择、排序、增删、批量发送确认、相册网格、图片与视频压缩已有源码。确认界面支持静态照片定比例裁剪、旋转和水平翻转，可重新调整已应用的裁剪。视频可通过缩略图时间轴选段和移除音轨。安卓拍摄素材沿用同一确认流程。详见 [附件发送确认](V2_MEDIA_CONFIRMATION.md)。

Mac 和 Windows 混合拖入文件与文件夹时，按拖入顺序逐个打开文件夹的系统选择器。取消一个选择器只跳过该文件夹。打不开的路径或超出总数上限的文件夹选择会提示，其他可用项仍进入同一份发送确认。

## 阅读与消息操作

聊天相册按发送顺序排列。偶数项每行两张，奇数项第一张横跨整行，其余两张一组。整组说明显示在相册下方。之后如果编辑其他单张的说明，内容跟随该项显示，仍使用正文的链接和隐藏文字处理。

消息操作菜单将回复放在顶部，为引用、复制、编辑、收藏、置顶和媒体操作添加图标。撤回、取消发送和本地删除放在分隔线下方。Windows 可在聚焦消息时用菜单键或 Shift+F10 打开，鼠标右键点在相册某一项上时仍以该项为目标。消息行离开视图或被复用时关闭它的菜单。

三端可从附件消息菜单复制非空说明。相册说明从保存该说明的项目复制，Windows 也可通过相册行的菜单复制整组说明。复制使用正文的富文本转换，将隐藏片段替换为占位符；编辑或撤回导致当前来源失效时，不发布旧内容到剪贴板。

未保存的正文或附件说明在主动取消编辑、改编辑另一条消息或从消息菜单进入多选时需要确认。选择继续编辑会保留当前修改，并将焦点交回编辑框。安卓聊天顶栏返回也沿用这一确认。

Mac 和 Windows 从左侧会话列表切换时也沿用放弃编辑确认。确认后才打开目标会话，选择继续编辑会回到原来的编辑框。正在提交修改时保留当前会话，提交结束后可重新切换。

文字样式、代码、隐藏文字、链接、预览卡片、图片/视频/音频/文件的每种状态都要完整覆盖。图片缩放、视频播放与拖动、下载、取消、重试、另存、共享媒体分类和返回原消息需要衔接原聊天历史。消息菜单、多选、复制、回复、编辑、撤回、转发、收藏、置顶和日期/未读/搜索定位均需保留上下文。

聊天中的普通文件卡片集中显示名称、字节大小、传输状态和当前可用操作。接收端按状态提供下载、暂停、继续、重试或保存。仍在上传的文件保留准备或传输提示。自毁附件沿用原有保存限制。Windows 支持在文件卡片的按钮或所在消息行用键盘操作，显示文件详情失败时以通用名称提示。macOS 可在卡片中重试读取本机详情。

桌面进入消息多选后，Shift＋点击把上次选中的消息到当前点击消息之间已加载的可选消息加入选择，仍受每批 100 条上限限制。

三端聊天相册在多选期间保留网格。点击某张照片或视频只切换该项，勾选状态显示在对应缩略图上。Windows 聚焦相册行后，左右键进入或切换焦点所在的缩略图。Enter 或空格打开该项，在多选期间改为切换选中状态。菜单键和 Shift＋F10 打开当前项的操作菜单。键盘焦点、窄窗口下的网格和批量操作留待统一验收。

三端可在共享媒体内按文件名或可见网址搜索当前分类，查询在本机完成。修改搜索词后回到第一页。链接结果按匹配的消息分页，每页最多 40 条，页内只显示命中的可见网址。

共享媒体读取失败时可重试当前页，保留分类、日期和搜索条件。三端区分临时读取失败与附件已失效，并在预览内提供读取重试。当前附件仍有效但本机缓存不可用时，在同一预览里显示下载控件。下载完成后原位置显示或播放媒体。撤回、到期或附件不再匹配时关闭预览。

三端打开共享媒体时会核对附件仍与选中的项目一致。关闭预览或切换页面后，尚未返回的打开请求不会再替换当前画面。退场动画期间也会停止处理旧的打开请求。

共享媒体的日历可定位到选中日期结束前的最近项目，再向更早的历史翻页。日期与关键词可同时使用，切换分类时保留日期。点「所有日期」恢复完整时间范围。

共享媒体可跨页多选同一分类中的照片、视频、音频、文件或链接，每批最多 100 条消息。转发打开收件人确认，收藏沿用消息收藏的加密流程。链接条目对应原消息，批量操作作用于原消息。修改关键词、日期或分类时结束选择。

照片和视频在多选时保留缩略图网格，角上的圆形标记显示选中状态。也可以从单张缩略图的菜单开始选择。

三端已接入聊天内的音频播放、暂停、进度跳转及 0.5× 到 2× 的七档倍速。打开同一会话里的另一条录音时沿用所选倍速。每个客户端只保持一个聊天音频播放器，切换会话、通话占用或离开应用时释放。播放器沿用加密媒体读取。Windows 的播放器随消息行卸载而释放，返回时可手动重新播放。 [Telegram Android 播放速度选择](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/Components/AudioPlayerAlert.java#L645-L665)

三端从共享媒体或聊天中的单条照片、视频消息打开预览后，可按消息时间连续浏览会话中本机已有的照片和视频。安卓在照片或视频画面上横滑切换。单指横向手势与纵向关闭分别判定，缩放和播放进度条保留自己的手势。触发距离为视口宽度的三分之一，快速横滑可提前触发。桌面方向键可切换媒体，Mac 的进度或音量滑块获得键盘焦点时由滑块处理方向键。关闭预览返回原聊天位置，或返回原共享媒体分类和分页。直接打开相册时仍按相册顺序浏览。 [Telegram Android 媒体手势源码](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L19285-L19319)

Windows 的聊天和共享媒体视频缩略图从本机附件读取流取首帧。缩略图只在内存生成，最长边 384 像素，取帧串行处理。视频格进入视口后才请求缩略图。系统解码器无法取帧时保留播放按钮，供用户打开播放器。

三端聊天相册的缩略图条随下载状态更新。未下载项显示下载或暂停等状态，辅助功能可读取具体状态及下载进度。滑动或点击切换后，当前项会定位到缩略图条的可见区域。

在聊天中点击尚未下载的单张照片、视频或相册中的一项，可先打开该项的预览页，并在原位置开始、暂停或恢复下载。

Mac 的全屏和普通媒体预览可播放普通 GIF 附件，沿用本机动画解码和可见窗口的播放限制。GIF 在内存中解密并逐帧渲染。超过 32 MiB、300 帧或 2048 像素边长时尝试显示首帧。

从聊天预览切换到已下载的接收照片或视频时，三端先校验本机加密文件，再显示原图或启动播放。发现缓存缺失或损坏时沿用原下载队列。安卓相册可先滑到目标页，在校验期间显示缩略图与进度指示。普通照片和视频在替换缓存入队后仍可留在对应项，继续控制下载或返回原消息。

桌面静态图片预览提供双击缩放、放大缩小、适合窗口和有限范围拖动。Windows 滚轮以光标为缩放中心，Ctrl 加减键缩放、Ctrl+0 复位。Mac 支持触控板捏合。打开预览时键盘焦点进入预览，普通关闭后尝试回到之前的控件。Windows 在播放器内也处理 F11 和 Escape，Escape 先收起菜单或退出全屏，再关闭预览。实际手势和焦点行为留待统一验收。

聊天媒体预览可从工具栏进入全屏。安卓隐藏系统栏，返回键先退出全屏。Mac 使用系统全屏并暂时收起聊天侧栏，Windows 按当前显示器边界扩展为无边框窗口，也可按 F11 切换。退出全屏保留当前媒体，关闭预览恢复原窗口和返回原消息的路径。系统栏和窗口切换留待统一验收。

安卓点按预览画面可淡入淡出顶栏、说明、缩略图条与播放控件，播放继续，双击仍用于照片缩放。退出全屏会重新显示控件。相册有其它成员撤回或到期时，分页仍锚定当前消息 ID；只剩当前项时收起缩略图条，保留预览和全屏状态。当前项失效仍关闭预览。[Telegram Android 单击行为](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L20831-L20920)

Mac 照片和全屏播放的视频在指针空闲时淡出工具栏、说明和缩略图，移动指针恢复。暂停播放、操作滑块或停在工具栏上时保留控件。Windows 的照片与全屏视频同步淡入淡出原生顶栏、说明和缩略图，播放器内输入也可唤回它们，视频继续使用浏览器原生播放控件。系统减少动态效果时省略淡变，读取错误的重试入口仍可见。[Telegram Mac 指针处理](https://github.com/overtake/TelegramSwift/blob/561169337e838c3281f7cfe24652757a5b522df9/packages/GalleryUI/Sources/GalleryUI/GalleryPageController.swift#L567-L601) [Telegram Desktop 控件显示](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/media/view/media_view_overlay_widget.cpp#L3217-L3264)

从聊天、相册或共享媒体打开的预览可通过工具栏保存当前已下载的照片或视频。三端调用系统保存界面，并在导出前和完成前确认原消息及附件仍可访问。自毁消息不提供导出。

三端可从媒体预览转发当前项目，沿用收件人选择和发送确认。聊天预览还可直接回复当前项目并把焦点交回输入框。相册翻页时，操作跟随当前显示的项目。自毁消息不提供转发。 [Telegram Android 媒体转发、回复与定位入口](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L13401-L13429)

三端从媒体预览的三点菜单进入共享媒体、原消息、回复、转发和另存。打开同一会话的共享媒体时，照片和视频进入混合媒体页，音频进入音频页。从共享媒体内部打开的预览直接关闭即可回到原分类和分页。 [Telegram Android 查看全部媒体入口](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L13414-L13429)

共享媒体在当前窗口内分别记住各分类和分页的滚动位置。改搜索词或日期范围后从第一页开始。Mac 以可见条目为锚点恢复，Android 和 Windows 沿用原生滚动位置。

媒体预览显示当前项目的消息说明，内容较长时可在下方单独滚动。说明沿用聊天正文的链接和隐藏文字交互，编辑提交后随当前项目刷新。参考布局见 [Telegram Android 说明与缩略图位置](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L3164-L3182)、[原生 Mac 说明布局](https://github.com/overtake/TelegramSwift/blob/561169337e838c3281f7cfe24652757a5b522df9/packages/GalleryUI/Sources/GalleryUI/GalleryPageController.swift#L981-L999)和 [Windows Desktop 说明布局](https://github.com/telegramdesktop/tdesktop/blob/157f5cfc85e2dd1fa67f129a5e31a81db5ddeb19/Telegram/SourceFiles/media/view/media_view_overlay_widget.cpp#L1967-L2034)。

三端的音视频预览菜单提供 0.5× 到 2× 的七档播放速度，速度随当前播放器保留。安卓播放器增加静音，并在进度条拖动期间显示目标时间，松手后跳转。播放与说明操作留待统一实际验收。

三端的媒体预览在本机解码或播放失败时提供重试。照片在当前页重新读取，音视频尽量回到失败前的播放位置并沿用倍速与静音设置。重试继续通过加密对象读取，已发现缓存损坏时沿用已有的重新下载流程。Windows 的 WebView2 初始化或主播放器进程失败时，会在同一页显示原生重试按钮。重试释放旧播放器的读取流，再创建新的私密播放器并从头打开同一媒体。重试、播放位置和退场期间的行为留待统一实机验收。[WebView2 进程故障处理](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-related-events)

引用、编辑、录制、选取、媒体浏览和通话中断后，应恢复正确的会话、草稿、焦点与滚动位置。已读、送达、未读数、下载和联系人状态通过提交后的数据更新刷新，不能靠退出会话重进。

三端在浏览旧消息时提供返回最新消息的按钮和当前未读数，多选期间隐藏该入口。桌面只在读取最新消息成功后定位，保留失败前的消息窗口供重试。安卓遇到分页读取错误时保留聊天历史的重试入口。

切回会话时，以仍可见的有效消息为锚点恢复阅读位置。进入会话和手动定位首条未读时，三端按当时的数据库状态选取消息，跳过已到期、尚待清理的记录。初次定位到历史锚点或首条未读时，暂停可见区域的已读计算，等定位完成后按实际显示的消息更新。

Mac 和 Windows 向前或向后加载一页历史时，尽量把已在视口中的消息留在原位置，恢复位置期间暂停计算可见已读。已停在最新消息时，调整窗口或输入区高度后继续贴住底部。

三端在宽屏中将消息区和输入区对齐到居中的内容区域。安卓和 Mac 按聊天区实际宽度测量文本气泡，为头像、多选和边距留出空间。Windows 的附件与贴纸面板以及返回按钮随内容区移动。桌面缩放窗口或侧栏时，Windows 用正在阅读的消息及其偏移恢复视口，Mac 在 macOS 15 及以上仅在跟随最新消息时使用底部尺寸锚点。重新布局期间暂停旧的可见已读候选，布局稳定后按新视口更新。[SwiftUI 按用途设置滚动锚点](https://developer.apple.com/documentation/swiftui/view/defaultscrollanchor(_:for:))

Windows 和 Mac 切换会话时显示加载状态，在后台读取首屏消息、回复及相册资料。快速切换或显式跳转后，只应用当前会话和定位请求的结果。在历史锚点恢复后才按新页面的实际可见范围提交已读。

安卓处于最新消息时，键盘、附件面板或贴纸面板改变聊天区大小，以及连续收到新消息，都在下一次列表布局时继续对齐底部。手动滚动和主动定位历史消息时优先保留用户的位置。面板覆盖或历史定位期间隐藏浮动的最新消息、引用返回和搜索导航按钮。

恢复阅读位置时会重新确认锚点仍存在且未到期。位置已经失效时打开最新历史。引用仍可定位到有效的撤回占位。

三端加载聊天历史时会跳过读取时已到期的消息。安卓计算定位偏移和读取分页时使用同一时间点，避免在翻页中因时间条件变化而重复或跳过消息。桌面端加载定位窗口时，目标和两侧分页共用同一时间点。后台到期清理仍负责移除已经显示的到期消息并刷新列表。

从引用、置顶、共享媒体、日期或首条未读跳转到同一聊天内的消息时，保留原来的阅读位置。点返回箭头按顺序回到上一处。定位期间暂停按可见范围发送已读回执。

置顶栏可用图标打开全部置顶，图标提示跟随界面语言。置顶列表、发送设置和待发队列覆盖聊天时，底层聊天不会继续报告可见已读。

三端日期跳转定位到所选日期的第一条可显示消息，跳过已撤回和已到期的消息。查找范围使用本地时区中当天与次日的起点。当天没有消息或无法读取历史时保留日期选择，以便修改日期或重试。日期跳转和首条未读入口沿用界面语言。安卓日历打开期间暂停底层聊天的已读回执和活动状态。

点「跳到最新消息」后，三端在加载成功前保留之前的返回位置。读取失败时可在聊天里重试这次跳转。安卓等待分页已加载到最新端点再滚动，避免直接把历史分页的第一条当成最新消息。

隐藏文字还要覆盖会话列表、置顶摘要、搜索、转发确认、引用和通知等衍生显示；正文控件隐藏完成不代表全部衍生界面已完成。代码/链接也需明确复制、打开默认浏览器和长按/右键行为。

## 覆盖方法

实施时沿每条用户流程继续到成功、取消、失败和恢复结束，覆盖相关状态和输入方式，不只替换用户举例的按钮。参考记录、功能编码、最终视觉/动画制作和实际验收分别记进度。当前遵守用户要求，只编码，不启动独立复核、构建或测试；所有代码写完后暂停，等待用户准备好再统一进入后续阶段。
