# 单聊置顶消息

当前为源码实现，尚未统一编译、运行或验收。与聊天列表中的会话置顶不同：本功能让单聊双方同步置顶已有消息，查看置顶列表并返回原消息。

## 加密与身份

`chat.pin` 是 Signal 加密应用事件，复用身份认证、持久队列、重复事件记录和事务提交；不向中继提交明文消息 ID、置顶对象、作者或操作类型。没有新增身份、根种子副本或外部密钥。

事件绑定 `message_id` 与原消息根身份 `author`。事件执行人取自认证后的会话发送者，不信任客户端 JSON 自称的操作人。只允许当前单聊两方操作，在联系人已接受、未拉黑和未被证实销毁时接收。已有消息必须属于该会话、作者匹配且未撤回。

事件字段包括 `message_id`、`author`、`sequence`、`pinned`、`observed` 和可选的 `notify`。共享解析器检查规范 UUID、账号、整数范围、布尔值、最多两个不重复观察项和未知/重复字段。三端新增置顶确认，发送者可选择通知对方，默认安静同步。取消置顶不会发送通知。

## 乱序与并发

每条原消息为每位参与者保存一个独立递增序号、最近置顶添加序号和已移除序号。操作人只能推进自己的寄存器，不使用设备时间决定置顶胜负。

- 后到的旧置顶不会覆盖该操作人已提交的更新取消操作。
- 取消置顶携带本地已经观察到的两方添加序号，移除这些添加。
- 未被取消操作观察到的并发重新置顶会保留。用户刷新后可再次明确取消。
- 对方提供的移除序号只能作用到本地已认证的对应寄存器范围，不能用虚构的大数预先取消未来的本地置顶。
- 置顶先于原消息到达时可以暂存，但未收到/未验证原消息前不显示内容。未知目标新时钟限制为每会话 256 行、全库 8192 行；现有记录的后续归并仍可进行。越限事件不创建记录，不形成无限待处理对象。
- 系统提醒只在新的置顶序号提交后发出，且原消息必须已存在并有效。迟到的原消息仍会显示其置顶状态，不补发旧提醒。后台提醒遵守会话静音，只显示通用的置顶提示。点击沿用原消息定位和应用锁。

更新时钟、加入加密发送队列在同一数据库事务内完成。`chat.pin` 也纳入 `send_related_events`：原消息有已进入加密外发的关联置顶时，不把原消息误判为尚未发出并允许取消。

## 数据与生命周期

三端 `message_pin_clocks` 保存在各自 SQLCipher 库，复合主键为会话、消息、原作者和操作人。Android 有保留现有数据的 11→12 Room 迁移。索引与删除/撤回触发器在各端安装，原有发送关联触发器升级时替换为包含置顶的定义。

置顶只引用原消息，不复制附件，也不单独拥有媒体对象。删除/撤回原消息会清除对应时钟；清会话历史也清除尚未收到目标的时钟，删除会话按外键级联清除。收藏消息的独立媒体所有权维持现有规则。

置顶栏、置顶列表和消息菜单都排除已自毁或超出本机历史保留期限的消息。目标仍在等待清理时，本地置顶和晚到的对端置顶事件也不再接受，避免为即将清理的消息发出提醒。跳转沿用聊天历史的到期检查。

三端从当前会话的有效置顶记录查回原消息，双方同时置顶同一条消息时只显示一条。列表按原消息时间和 ID 逆序，每页最多显示 50 条，额外读取一条判断是否还有下一页。预览显示有界正文、附件说明或文件名。

## 功能入口与即时刷新

三端已加入消息菜单的置顶/取消、会话置顶栏、分页列表、列表取消和原消息定位。定位复用现有历史分页窗口，不加载全部历史。打开列表不会直接把整段聊天标为已读。

置顶摘要以主题色标记，与切换和列表按钮分开。三端从消息菜单或列表取消置顶时先提示该操作会同步给双方。确认绑定最初选中的消息，期间列表刷新或选择变化不会改动目标。

有多个置顶时，三端顶栏显示「下一条置顶消息」图标。切换按消息时间从新到旧，到末尾回到最新一条。手动切换后，顶栏按消息 ID 保留正在浏览的置顶。对方新增或移除其他置顶时，摘要仍指向原消息。点摘要跳转，旁边的列表图标可打开全部置顶。当前置顶被取消、撤回、删除或到期时，顶栏恢复到最新的有效置顶。

Android 用声明的 Room 实体观察置顶/消息变化；进入消息菜单时读取当前置顶状态。消息行使用稳定消息 ID，回执状态不再改变行的列表键。Windows 在数据库变化刷新时更新置顶栏，菜单打开时获取当前状态；列表更新保留仍存在的选中项。Mac 读取当前历史窗口中消息的置顶状态并通知 SwiftUI，列表按数据库提交事件合并刷新。取消置顶直接操作原聊天中的状态，不删除原消息。

三端翻页失败时保留上一个成功加载的列表，并提供对失败页面的重试。取消置顶或收到对端操作后，若当前末页变空，列表自动回到最近还有记录的一页。置顶列表的按钮、日期和错误提示跟随界面语言。

这些是现有原生界面中的功能入口，完整 Telegram 布局、视觉、菜单和动画仍未重做。统一实机阶段还需要覆盖双向离线/乱序操作、并发重置顶、撤回/清理/Reset、已发媒体取消限制、分页与跳转、静音和快速切换会话后的即时刷新。没有新增测试代码或执行测试。
