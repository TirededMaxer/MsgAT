# V2 加密草稿与发送一致性

状态：2026-11-09，三端实现与部分实际操作完成，完整验收仍在进行。

## 存储与身份

草稿沿用当前身份的 SQLCipher 数据库和现有数据库密钥，不创建新的根种子，不使用明文偏好设置、临时文件或独立草稿文件。

三端使用相同的 `conversation_drafts` 表：

| 字段 | 用途 |
| --- | --- |
| `peer` | 会话标识，主键，关联会话删除时级联清理 |
| `token` | 该会话生命周期的随机标识；删除后重新建立会话会生成新值，不是加密密钥 |
| `revision` | 进程内递增修订号，从库内最大值继续，不依赖设备时钟 |
| `text` | 草稿正文，最多 1 MiB UTF-8，不静默截断 |
| `reply_id` | 被回复消息的 ID；重开时仅恢复同一会话中仍存在、未撤回的消息 |

草稿与解锁后的其他内容一样，会在应用进程内存中短暂存在。SQLCipher 加密落盘不等于进程内存隔离，也不阻止已完全控制系统的攻击者。

## 保存和发送

每个客户端使用一个后台合并写入器。编辑内容按会话合并，写入校验生命周期标识和修订号，迟到的旧写入不能覆盖新内容，也不能重新创建已删除会话。写入失败保留待写内容并重试，界面显示固定错误文案，不在日志中输出草稿。

文字发送保留输入内容，直到消息与持久发送队列写入成功。清理对应草稿和消息入队位于同一数据库事务；随后只在当前编辑状态仍匹配原快照时清空输入区。网络传输失败由持久队列重试，不撤销已经成功的本地提交。

图片、文件和剪贴板图片使用相同的事务边界，但成功后只消费回复状态，保留文字草稿。选取取消、图片转换失败、文件导入失败、联系人尚未同意和入队失败均不提前清除回复。导入期间的新输入或新回复有更高修订号，旧任务不能覆盖。转换前捕获的旧快照如果在正式发送前已被修改，只用于发送该附件，不再清理当前草稿。

同一个编辑快照正在提交时，输入区阻止重复提交该快照。附件组批量发送仍属于后续相册/多附件功能，不能用此处的单附件路径当作已实现证据。

打开会话会等待该会话已有发送操作完成本地提交或失败，随后读取最新草稿，避免刚切走又切回时恢复提交前的旧内容。此等待由协议协调器完成；界面被销毁不会代替协议层宣布提交成功或失败。发送前还在事务中确认会话生命周期未改变，避免导入途中删除并重建会话后向新会话错误提交。

片段引用随草稿修订保存原消息 ID、UTF-16 选区和原消息内容校验值。切换或重开会话时重新解析原消息，自毁、撤回、删除或发生编辑的来源会使旧选区失效。发送提交时重新校验选区，并与原回复状态一起消费，失败保留当前草稿。

## 当前证据与缺口

- 三端此前草稿代码通过编译，安卓 lint 通过；附件回复修复后的构建记录位于本机忽略目录中的 `*-attachment-drafts-build.log`。
- Mac 的 Unicode 多行草稿在退出重开后恢复；最新版 QA One 实际将该草稿离线写入消息列表，输入框随本地提交清空，消息显示等待发送。隔离中继当时未启动，因此这不是送达验收。
- Windows 已实际验证应用更新/重开恢复草稿，以及向待同意联系人发送失败后保留草稿。这些操作使用较早的草稿包，不能证明后续附件修改已验收。
- 安卓已安装版本仍早于草稿修复，手机下载目录中的已暂存 APK 等待用户覆盖安装。后续编译没有覆盖该待处理文件。
- 附件引用取消/失败/成功、完整跨会话隔离、恢复引用、删除后重建、发送中退出和身份销毁中断等仍需实际操作补齐。草稿实现不代表搜索、转发、收藏或全面 UI 重构已经完成。
