# 媒体发送准备、进度与取消

状态：2026-11-10，直接文件/媒体、剪贴板图片和表情发送已接入三端源码；未构建、未运行、未验收。本模块沿用根种子、对象加密格式、SQLCipher 事务与对象所有权，不新增数据表或持久媒体所有者。当前是功能入口，最终 Telegram 原生布局与动效仍待制作。

## 准备与入队的边界

每次直接媒体/表情发送有独立的进程内 `ObjectPreparation`。界面选择、草稿与发送选项在本次发送开始时捕获；准备失败或用户取消不消费草稿、回复或发送选项。表情选择器区分 queued/cancelled/failed，取消不等同成功，也不按发送错误显示。

- `preparing`：可以请求取消，包括等待准备或进入消息协调器的阶段。
- `canceling`：取消标记已记录；等待正在进行的读写、分块检查与未提交对象清理结束，不立刻释放文件或外部权限。
- `committing`：协调器获得本次入队权，开始本地提交，不再承诺可取消。界面显示 Queuing，并隐藏准备取消按钮。
- `finished`：操作与必要清理已排空，释放进度句柄和界面观察者；这不是对端送达状态。

取消与进入提交在同一个宿主锁下决定先后。取消先取得权利时，后续提交入口失败；提交先取得权利时，取消返回不接受，既有消息事务继续。中继事实回执、已发送消息的撤回和队列取消仍使用各自原有规则，不用准备界面的临时状态替代。

Windows 的外部取消令牌也通知正在处理的原生工作；关闭表情窗口会请求取消并等待，已经进入提交时改为等待完成。Android 保持原来的操作所有权：调用方导航或协程取消不能让外部文档/剪贴板权限先于导入释放，显式准备取消由独立标记处理。Mac 的串行协调器与导入队列继续按现有顺序排空。三端均在 worker 与 staged-object 清理结束后才释放本次句柄；界面停止观察不会关闭资料库或提前销毁根保护。

## 图片压缩、视频编码和字节进度

进度卡片从准备开始就显示本批附件的件数，文件开始读取后更新当前序号和字节进度。标题、进度状态和取消按钮跟随界面语言。表情面板按任务类型筛选准备进度。

三端在裁剪、静音或压缩触发转码时显示视频编码状态，并使用编码器提供的百分比。转码完成后，以原有附件序号进入加密导入并重新计算字节进度。可选压缩回退到原文件时也会重置进度。Windows 用准备状态的修订号忽略延迟到下一阶段的编码回调。

可选的 JPEG／静态 PNG 压缩显示独立的不定进度，随后切换为本项附件的加密导入进度。压缩结果没有节省空间时继续导入原件；取消后不进入原件回退或入队，确认页仍保留本批的选择和修改。macOS 在每次分块读取和读写阶段之间检查取消，Windows 将准备取消传给图片编解码操作。平台编解码器如果无法中断当前调用，取消会在调用返回后落实。

Rust 安全核心增加有界、进程内的准备表，最多 16 个活动句柄；界面每个模型最多接纳四项准备。句柄为随机 256 位标识，不携带文件名、路径、对象清单、正文或密钥，不写入数据库、日志或网络包。退出进程后它自然消失。

JSON 原生桥新增 create_object_work、object_work_status、cancel_object_work、report_object_work、close_object_work。文件导入/重新加密接口接受可选 work_id，旧调用省略该字段时行为保持兼容；这不是客户端与中继的协议。三端分发必须使用同一批当前原生库源码，不能把新增客户端源码和旧动态库混装。

原生文件导入与重新加密在 64 KiB 分块边界检查取消，写完一块后更新原子字节计数；最终同步和对象提交前再检查。已知大小的剪贴板字节及 Android 非 seekable 文档使用同一控制器，在宿主分块读写中检查、报告。Android 未知长度文档的第一次有界扫描显示不定进度，知道长度后才显示百分比。导入阶段的百分比表示当前附件的字节处理量，达到 100% 后仍可能需要验证、同步和入队。

界面只在活动准备期间约每 200 ms 读取这些进程内计数，使用修订号防止旧快照把取消/提交状态覆盖回 preparing。空闲时没有准备轮询；进度查询不读取 SQLCipher、解锁根种子或解密媒体。停止观察后的回调不能重新添加已移除项目。底层文件提供者的一次阻塞读写必须先返回，取消在下一检查点落实，不声称能瞬间打断任意系统 I/O。

发送确认页准备附件时，安卓返回键及桌面的 Escape 与进度区的取消按钮发送同一个取消请求。取消完成后返回原确认页，保留附件、说明、编辑和发送选项。进入本地提交阶段后，界面继续等待该批完成。Windows 确认窗口通过已有的进度更新刷新控件。

## 清理与所有权

文件创建前仍先登记 staging。原生操作取消/失败会清理自己的 part/已完成但未返回的对象；宿主继续按既有暂存日志清理未提交副本。成功时，媒体元数据、消息/定时所有权和 staging 移除共用原来的单个事务。没有把进度句柄当作媒体所有者，也不从界面直接删除文件。资料库独占租约、传输 pin 和退出/Reset 排空顺序保持不变。

## 剩余工作与统一验收

持久转发队列已有独立的分块进度及批次取消，见[转发任务](V2_FORWARD_TASKS.md)。三端在聊天及共享媒体浏览器中收藏消息时，准备卡片显示正在复制的附件序号与字节进度，包含可用的网页封面。进入数据库提交阶段前可以取消，保留当前选择并清理暂存副本。提交阶段显示正在收藏。

相册、压缩和说明见[发送确认](V2_MEDIA_CONFIRMATION.md)。三端发送带网页封面的文字消息时，输入栏显示封面的加密准备进度。入队事务开始提交前可取消，保留正文、回复和发送选项，并清理未提交的封面对象。普通文字与无封面的链接预览沿用原发送路径。
