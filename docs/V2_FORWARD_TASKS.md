# V2 持久转发任务

2026-11-09 源码检查点。三端已接入对应实现和必要操作入口；按用户要求，本轮没有构建、安装、运行客户端或执行运行测试。这些源码不能作为重启、取消和三端互通已经通过的证据。

## 存储与提交

任务位于现有 SQLCipher 库的 `forward_jobs`，包含随机任务 ID、版本化请求、创建时间、状态和固定错误码。请求只保存源消息 ID、来源范围、目标身份、隐藏署名/说明选项以及来源指纹；不额外复制正文、根种子、附件内容密钥或下载凭据，不创建明文队列文件。数据库保护继续沿用当前根身份派生链。

来源指纹使用 SHA-256，对域 `msgat/forward-source/v1`、收藏来源标记、来源身份、消息 ID、类型、正文、说明、对象清单、消息时间与原日期依次编码。每个字段使用 ASCII 十进制 UTF-8 字节数和冒号作为前缀，空值使用 `-1:`；非空字段随后写入 UTF-8 字节。指纹的用途是检测排队后原内容变化，数据库的保密和认证仍由 SQLCipher 承担。

排队时和实际准备前均检查联系人状态、来源存在与内容。等待下载时不复制旧的内容密钥。附件可用后，仍按每个收件人创建独立加密副本，沿用已实现的分块重新加密操作。提交前再次核对来源及联系人。

整个批次的消息、附件引用、转发标记、发送队列和删除任务记录在同一次事务中完成。事务失败则保留任务并清理本次尚未提交的副本；成功后由普通消息发送队列负责重连、密文重试及送达状态。任务不会在数据库里先标成成功、随后另起事务创建消息，因此中途退出不会仅凭一个成功标记跳过消息，也不会再次执行已提交的任务。

## 状态与操作

- `waiting`：等待本地附件下载或进入准备阶段。
- `preparing`：当前正在准备独立的加密副本。每个客户端同一时刻只准备一个持久转发任务。
- `failed`：原消息变化/消失、收件人失效、准备失败或超过等待期限。保留固定错误码供界面说明，日志不写请求或正文。
- 成功：任务记录与消息入队一起删除，用户到目标聊天查看普通消息状态。

单次最多 100 条消息、20 位收件人，最多保留 20 个待处理或失败任务。等待超过七天会显示过期，用户可主动重试；重试仍使用原来源指纹，不会偷偷改成新的正文。原消息已编辑/撤回时，应重新选择当前消息建立新任务。

等待源附件或准备转发时，按对象清单计算每位收件人的密文副本空间，再加上去重后的源附件和链接封面剩余下载量，并保留 256 MiB 余量。续传已落盘的完整分块计入现有文件，收藏按一份副本计算，逐对象下载和复制仍各自检查空间。空间不足时，队列显示失败原因，用户释放空间后可用原任务重试。这是空间估算。真正的写入失败仍由整批回滚和副本清理处理。没有媒体对象的批次跳过该预算。

三端主菜单都有“Forwarding queue”入口，可看状态、重试及取消/移除。转发面板成功提示改为“Forwarding queued”，不把本地排队称为送达。附件下载完成会唤醒队列；另有有界合并唤醒和 30 秒恢复检查，避免空闲时持续轮询。批内消息顺序继续使用排序后的新 ID 与同一批次时间。

队列显示收件人、当前加密副本的序号与字节百分比。进度条按已准备的副本份数展示整批进度，进入本地提交时显示入队状态。取消确认绑定打开确认框时的任务 ID，队列刷新或选中项变化不会改变取消目标。

等待下载时，队列显示还有多少条消息缺少附件或网页预览图。计数在队列重新检查源消息后更新。

对等待下载且来源是聊天的任务，可从队列定位到第一条未下载的原消息，也可直接请求下载本批缺少的附件或网页封面。点击后重新核对任务、来源消息及收件人，再恢复现有下载队列中的传输。下载完成后由原转发任务继续处理。队列同时显示静默及定时选项，载入失败后可直接刷新。原消息已变更的任务需重新选择来源，队列只提供移除。

准备过程中读取源对象失败时，三端会检查失败对象的密文长度和摘要。确认缺失或损坏后，在同一事务中重新核对任务、来源、收件人和缓存引用，并把收到的原附件或网页封面加入重新下载。原转发任务回到等待状态，下载成功后重新准备整批副本。每次任务启动或手动重试最多自动修复一个对象，重启保留已尝试标记。收藏、副本或有其他引用保护的对象不会被自动清理。仍可从聊天或转发队列查看和重试可下载的来源。

中继明确返回必要附件或链接封面不可下载时，转发任务显示对应的失败原因。网络超时和离线继续沿用等待及退避。手动重试会核对任务与原消息快照，只重新请求本任务中被标记为不可下载的来源。请求和任务回到等待在同一次事务中完成。选择省略链接预览后，封面下载结果不影响任务。

取消通过事务删除尚存的任务，再请求准备器停止；消息提交事务也检查任务仍处于 `preparing`。取消先提交时，新消息不能再入队。消息入队先提交时，取消返回“已经完成或状态已变化”，不会声称撤销已经入队的消息。已入队消息的取消/撤回属于普通消息生命周期。

## 定时与静默

选择「省略链接预览」时，任务保留原消息文本和链接，跳过网页预览元数据及封面的下载和复制。该选择随任务持久化为 v3，重启后继续生效。现有 v1、v2 任务沿用原行为。

转发确认中的发送选项独立于聊天输入框，保存在加密任务请求 v2 中；旧 v1 请求按即时、非静默处理。复制完成后，同一提交事务将整个任务替换为普通发送项或定时持有项，并转移媒体所有权。定时项到期前不上传其新副本，客户端运行且连接后才释放。若等待下载/准备已经超过所选时间，则进入到期流程；不会丢弃选择或伪造准点送达。队列后续改期、发送或取消见[发送控制](V2_SEND_QUEUE.md)。最新源码仍未构建或验收。

## 重启与退出

启动时将未完成的 `preparing` 恢复为 `waiting`，重新读取来源并检查指纹；已经成功入队的任务不再存在。没有完整下载的对象继续等待原有媒体传输恢复，不转发缺失文件。

Windows 关闭队列时取消并等待工作任务，再结束导入和安全协调器。Android 将准备任务纳入独立但受关闭流程管理的协程域，在串行数据库提交完成前保留副本所有权；关闭时先取消/等待转发，再关闭附件及消息处理器。消息处理器的终止路径会关闭通道并通知尚未处理的操作，防止调用方一直等待。Mac 停止队列接纳、取消准备标记，再按原消息协调器和导入队列的屏障顺序退出；关闭后的队列回调不再访问数据库。
