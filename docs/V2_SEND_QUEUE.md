# 发送控制与定时队列

状态：2026-11-10，三端底层、原生发送选项、队列入口、静默通知和转发选项已有源码；未构建、未运行、未验收。直接媒体/表情的准备进度与取消也已接入；完整通知/会话设置、其他准备任务和最终 Telegram 交互仍待完成，不能把当前源码称为已验收的完整功能。

## 当前实现

三端直接文字、媒体/文件、表情发送接口接受 `SendOptions(sendAt,silent)`，默认与此前相同。Windows 公共 MessagingService 也传递这些选项。三端输入区域均有发送选项入口和当前选择摘要，可清除下一条的选择；静默/定时选项同时覆盖直接文字、媒体/文件和表情。发送前捕获选项修订号，入队成功后只清除匹配修订，不覆盖用户后来选择；失败保留选项与草稿。桌面切换会话不沿用另一会话选择。现有安装包未改动。

`silent` 是 Signal 加密正文中的可选布尔字段，应用事件解析拒绝非布尔值及未支持属性；中继不解析它。接收路径保留通用可见通知/未读状态并关闭声音与振动。Android 使用独立的无声无振动通知通道并设 silent；Mac 使用 UserNotifications，静默消息不设置 sound；Windows 托盘改用系统 Shell 通知接口的 NIIF_NOSOUND，尊重系统勿扰/安静时段，不创建自定义弹窗。三端默认通知正文为“New message”，不含聊天正文；前台与系统通知权限仍按现有边界处理。通知隐私/会话静音设置将在统一设置模块补齐。Windows 原生接口参考 [NOTIFYICONDATAW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw) 和 [SHQueryUserNotificationState](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate)。

定时消息先进入本机 SQLCipher 的待发送事件，正文、引用、原始媒体清单和静默选择在本机保存。`scheduled_sends` 保存时间和 waiting/failed 状态，`scheduled_objects` 登记其媒体所有权。正文消息不提前插入普通聊天记录，也不提前开始上传定时媒体。到期且连接可用时，最多处理 16 条：在一个事务里更新实际事件创建时间、解除 held 标记、创建消息和上传任务、转移媒体所有权并删除定时记录。正文仍通过原有 Signal/密文中继链路发送。

时间是 UTC Unix 毫秒，允许媒体准备期间所选时间已经过去，到期后按实际释放时间创建事件。日期/时间界面使用本机时区并转换 UTC，拒绝已过期时间与夏令时不存在的本地时刻；重复时刻选择较早的真实时间。发送前再次检查选择仍在将来，准备期间过期则按到期处理。当前客户端必须在运行并连接后才能释放；进程关闭、系统停止或无网络不能保证准点发送。没有把预先可解密的消息交给不可信中继来保证未来时间，因为那会允许中继/收件端提早处理。

## 有界发送和取消边界

发送循环先处理缓存的密文；只有八个位置的发送窗口仍有空位时，才逐条准备一个新 Signal 包并立即交给传输。不会先批量推进几十条发送步数、再把其中大部分留在未传输队列。`held` 的索引让普通发送跳过大量未来定时项，准备函数也独立拒绝仍有定时记录的事件。目录回复只缓存已验证的公钥声明（最多 128 个），不会在回复路径提前准备大量包；持久请求 ID 保留到真正准备提交，以便重连幂等重领。

普通内容消息的 `message_sends` 保存未确认送达时的不可变原始正文、种类、原始创建时间和首次尝试标记。创建消息或待发送事件的触发器捕获同一事务中的原始事件；送达/已读或撤回后删除重试副本，清历史级联删除。升级前无法证明从未交给网络的记录使用保守的已尝试标记，不新增“确认未发送”的保证。

`send_related_events` 跟踪同一消息的编辑/撤回控制包。交给传输前持久记录首次尝试，既覆盖原消息，也覆盖相关编辑；防止原消息等待封面上传、编辑内容却已经发出时仍误报可取消。取消还检查原消息和相关控制包是否已有缓存密文。若已经准备或可能交给网络，不返回取消成功；用户需要使用既有撤回语义。取消不是对已收件内容、独立引用/转发副本的销毁承诺。

可取消的排队消息会在同一事务内移除未准备事件、相关控制事件、上传任务和本地消息；媒体通过引用/暂存/传输 pin 的既有机制回收。定时项可取消、立即发送、改期或失败重试。直接媒体/表情在本地导入/复制期间已有独立准备进度与取消入口，见[准备控制](V2_PREPARATION.md)；当前队列管理接口仍只管理已提交项，不与尚未入队的准备操作混为一类。

## 重试与联系人变化

三端在首次加密前检查已验证密钥包的签名有效期。若密钥包在等待发送窗口或附件租期期间过期，客户端结束旧请求并申请最新密钥包，原待发事件继续留在加密库。若重连后使用同一持久请求 ID，中继在旧密钥包仍有效时返回原预留结果。旧包过期后，中继可在原收件人绑定下用当前有效包更新预留，已分配的旧一次性密钥不会重新进入可用池。

重试要求仍是自己未被撤回、未确认送达的消息，且对方已接受、未拉黑、未被根签名撤销。缓存仍在时恢复同一密文；原事件未准备时恢复原事件 ID/正文/创建时间。恢复需要的上传任务和下载租期检查，清理退避期限，不把“重新排队”称为送达。对于其后有本地编辑的消息，会补排当前编辑修订。附件说明的修订保留其类型标记。

拉黑/关系失效把既有 outbox 暂停为 `-2`，不自动恢复自己的内容消息；明确重试才能恢复。接收端事实回执可在重新获准且仍满足隐私规则时恢复。因隐私关闭取消的 Read 和根身份撤销使用终止状态，不能靠解除拉黑恢复；已读关闭同时覆盖暂停的 Read 并保留禁止补发标记。根签名撤销会删除已不可能重试的原始正文副本。定时事件被关系清理删除时，其所有者随 FK 级联清理。

真正的对方 Delivered/Read 比中继存储确认更强：三端据此结束对应普通 outbox 重试并清理其上传任务，再升级精确消息状态。避免中继确认丢失后还一直重发已送达内容；不会改变单勾/双勾事实含义。

三端在首次确认中继存储时记录一次送达恢复机会。超过 24 小时仍未收到对端加密回执，且仍在首次中继确认后的七天内，客户端在已连接的维护周期内重新排入原事件 ID 与密文。附件和链接封面复用原发送对象，重新通过现有租期检查后才提交密文。每个周期最多处理八条。对端已收到正文时，重复包沿用去重和回执重发流程，已读隐私规则照常生效。

收到对端回执、撤回、消息到期或联系人失效都会终止自动恢复。实时位置起始事件不参加这一恢复，避免在分享结束后发起旧位置事件。窗口外、缺少原附件或升级前已经处于中继确认状态的条目保留现有手动重试入口，仍受消息和联系人状态约束。

三端可点聊天中的发送中标记或失败标记，也可从消息菜单发起重试。附件上传进入退避时，媒体下方另有重试按钮。聊天里的取消和重试按会话及消息 ID 校验。联系人重新可用后，失败消息可用原事件重新入队，状态随事务和后续回执刷新。若对方仍不可用或已收到消息，重试事务会拒绝请求。

## 媒体所有权和退出

定时对象、重试原始对象分别由 `scheduled_objects`、`message_send_objects` 持有。后一类包含原始网页封面：当前编辑移除预览后，原事件重试仍可能需要它。两表已同时加入三端 `media_object_references` 和对应回收触发器；重试副本创建、确认/撤回/取消与正文所有权转移均在同一事务内。实际文件创建仍先登记 staging，所有者提交与 staging 删除共用事务，传输期间仍有 pin。

新所有者不会从数据库直接删除文件。删除最后所有者后进入既有垃圾日志，由进程资料库独占租约下的维护任务处理；正在操作的传输先排空。内容导入、共享核心、硬件根种子与资料库密钥逻辑不变。计划维护只比较内存期限，到期才提交工作；Android 协程、Windows 维护任务、Mac DispatchSource 均随原协调器停止并排空。下一期限失效会重新从带索引的 waiting 定时项计算，失败释放保留为 failed，避免无休止立即重放。

## 队列和转发入口

安卓长按文字发送按钮，桌面端右键点击该按钮，可直接静默发送，或选择日期和时间后将当前草稿加入定时队列。静默动作沿用已选择的定时时间。只有消息成功入队才消费对应版本的草稿与发送选项。

主列表菜单提供全局发送队列，三端聊天顶栏也可打开当前会话的队列。全局队列显示本机保存的联系人名称，可从队列项打开对应聊天；没有名称时显示账号 ID 前缀。队列操作、状态和错误使用当前界面语言。三端列表每页 50 条，提供刷新/前后页、定时项立即发送/改期、失败重试及尚可取消项的确认。列表依实际事务与发送交接刷新，不以临时界面状态充当送达事实。只读列表不会触发发送刷新通知形成循环；关闭窗口移除订阅并结束界面工作，不释放协调器仍持有的资料库或传输所有者。

三端可从聊天消息菜单取消仍在排队的消息，包括文字和附件。打开确认前按会话和消息 ID 查询队列，确认后复用队列的取消事务。确认期间如果消息已进入发送通道，界面会提示无法取消，聊天保留原消息。取消成功后，聊天随本地提交更新，正在上传的分块由既有传输检查点停止。

队列在同页刷新时沿用原列表，Windows 保留仍存在的选中项，安卓合并刷新请求以避免频繁更新取消尚未完成的读取。翻页失败保留上一个成功加载的页面，操作失败与加载失败分别提示。

发送队列保留原定时间。定时项到期且仍未释放时，断线显示「等待连接后发送」，已连接显示「等待发送」。打开的队列会在到期或连接状态变化后刷新这条提示。

三端发送队列会标明收件人当前不可用，或本机缺少原附件、链接封面的情况，并停用该条目的重试、改期和立即发送操作。无法从当前队列状态确定原因时，沿用「需要处理」。定时消息自动释放前和手动改期、立即发送、重试时都会核对媒体登记状态，释放失败则保留在队列中。执行普通消息重试时仍会核对联系人关系和原消息状态。聊天中的失败标记表示送达未确认，身份重置由收到撤销记录时的提示说明。

三端可筛选全部、定时发送和待送达消息。定时项按预计发送时间排列，普通待送达项按创建时间排列。筛选在分页前执行，只在还有结果时启用下一页。

从全局或单聊发送队列可编辑仍在本机等待的定时正文和非贴纸附件说明。编辑器加载完整内容，列表摘要按原有宽度显示并隐藏剧透。保存沿用原定时间、静默状态、回复和附件。正文修改后，仍然可见的同一网址保留已有预览，网址被移除或隐藏时同时释放预览封面的定时所有权。编辑操作不会请求新预览。

保存前在同一事务内核对会话、原定时间、原正文及本机持有状态。若其它窗口已修改内容、改期、取消或开始发送，编辑器保留当前输入并提示该项已变更。保存只更新尚未释放的本机待发送事件，不会产生发给对方的编辑事件。

已到期的普通消息在分页前从队列查询中排除。对旧列表执行取消或重试时，事务也会拒绝已到期的消息，后续由原有到期清理流程移除相关记录。

三端选取待加密事件和待提交密文时，先过滤已到期的正文、关联事件和回执，再应用批次上限。已到期的事件不会占用批次名额或触发预密钥请求。每次向中继提交密文前再检查一次，以覆盖选取批次后才到期的消息。

对定时消息执行改期、取消、立即发送或重试时，事务会比对队列显示的发送时间。如果消息已释放或被改期，队列提示状态已变并刷新。Windows 在确认窗口打开期间推迟队列刷新。

队列中的待送达消息可点「在聊天中显示」定位到原消息。从会话内发起定位时沿用聊天的返回位置。全局队列中的定时消息可以打开对应聊天。三端按会话 ID 和消息 ID 定位，会话名称缺失时仍可尝试打开。会话已删除或消息已撤回时提示队列项已变更。

转发确认有独立的发送选项，既不消费也不覆盖输入框选择。任务采用 v2 本地请求，保存 send_at/silent；v1 任务仍按即时、非静默解释。复制与来源复核完成后，在原来的单个事务中将整个转发任务替换为普通消息或定时消息和媒体所有者，再删除任务。定时转发对象同样先留本机，到期才进入上传任务；准备时已经超过选择时间则立即进入到期流程。
