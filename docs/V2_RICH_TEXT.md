# 文字格式显示

当前是源码编写阶段，未编译、未运行、未验收，完整输入格式操作和衍生摘要仍未完成。

## 共用格式

三端复用 Rust `render_message_text` 得到原生文本块和片段，不生成或执行 HTML、脚本、内嵌网页。当前输入语法是明确的轻量显示语法，不能宣称支持全部 Markdown：

| 语法 | 显示 |
| --- | --- |
| `**文字**` | 粗体 |
| `__文字__` | 斜体 |
| `++文字++` | 下划线 |
| `~~文字~~` | 删除线 |
| 一对反引号 | 行内等宽代码 |
| `||文字||` | 点击展开的隐藏文字 |
| 行首 `> ` | 引用块 |
| 独立行的三个反引号，可带语言名称 | 代码块及单独复制 |

原始文字仍进入原有 Signal 加密事件与 SQLCipher 数据库，编辑、转发和收藏保留原文；本轮没有增加独立加密密钥或明文文本缓存。显示解析按原有 48 KiB 文字上限处理，定界符配对限制堆栈深度、保留不匹配标记，不对任意输入运行正则回溯或递归 HTML 渲染。

## 三端控件

Android 使用 Compose 原生文本注释；Windows 使用 WPF 文本片段与链接；Mac 使用 SwiftUI AttributedString。解析移出 UI 线程，控件只保留自身当前文字的解析结果；修改源文字重置展开状态，Windows 控件卸载会取消待处理解析并释放展示状态。

正文/附件说明中的隐藏片段在展开前以占位文字替换实际展示字符串，辅助功能不从这些文本节点取得被隐藏内容。点击先展开，展开后可再操作其中的链接。隐藏状态不改变密文和原消息，也不声称阻止已授权收件端读取自己的数据。

HTTP/HTTPS 链接沿用默认外部浏览器。代码区不自动打开链接；自动网页预览的共用候选/接收校验也排除代码与隐藏片段内的 URL，避免卡片提前显示隐藏链接的目标内容。代码复制是用户明确操作，复制代码正文，不包括围栏。

安卓长按消息可从「消息链接」查看完整网址，并逐条打开或复制。独立显示的媒体说明可长按打开同一界面。隐藏片段和折叠引用中的网址只有完整显示后才可操作，桌面端的悬停和右键菜单也遵守这条规则。

三端默认折叠超过 12 行的代码块，可在原消息内展开和收起。复制始终取得整个代码块。若引用定位匹配到代码，显示完整代码以便看到高亮。代码区控件和格式解析失败提示沿用应用语言。

三端默认显示长引用块的前四个原始文本行，自动折行不计入。可在气泡内展开或收起。折叠部分的链接不进入可操作的链接区域，剧透仍要单独揭示。定位到引用块里的匹配文字时展开全文并保留高亮。消息复制、格式编辑和加密事件继续使用原有文本规则。

## 2026-11-10：输入与衍生摘要后续（只编码）

三端新增共享 UTF-16 选区格式操作，支持粗体、斜体、下划线、删除线、等宽、隐藏文字、引用和代码块。Android 有输入栏格式菜单及外接键盘快捷键；桌面使用原生输入框的格式菜单和 Ctrl/Cmd 快捷键。操作保留选区，桌面沿用原生撤销；输入法组合区未确认时不修改内容。不支持的代码围栏/跨行行内代码给出失败提示，不悄悄破坏源文字。

正文之外的会话/草稿摘要、引用、置顶、收藏和发送队列已接入共用安全摘要。搜索先处理完整原文的隐藏区域，再截取命中附近的片段，避免丢掉前方隐藏定界符后露出片段。对已经被数据库截断、缺少结束符的摘要，保守遮盖隐藏尾部；这个策略可能隐藏字面定界符之后的摘要，不影响打开原消息。收藏原文查看使用正文格式控件。系统通知仍保持原有不含正文的默认模式。

预览候选在输入过程中也保守排除尚未闭合的隐藏区域，不在用户还在输入隐藏链接时先抓取网页。列表中的附件摘要改为实际说明或文件名，避免把加密对象引用作为消息摘要。
