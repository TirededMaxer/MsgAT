# 可见消息与已读隐私

状态：2026-11-14 三端已接入可见消息已读与会话未读更新，待统一构建与实际验收。在线和输入状态见[活动状态](V2_ACTIVITY.md)。

## 用户行为

三端主菜单提供 Privacy → Send read receipts。默认开启，保留现有回执行为。设置保存在当前身份的 SQLCipher 资料库中，不写入系统偏好、服务端或另一身份。

关闭后，实际看到的消息仍在本机变为已读并减少未读数；对方最多收到 Delivered。以后重新开启，不补发关闭期间的阅读记录。已经发送到网络或已由对方收到的 Read 无法撤回。

前端提交当前视口内具体消息的 ID，每批最多 100 条，协调器在事务内再次校验会话、方向、未读和撤回状态。向上查看旧消息时遵循相同的可见条件。三端的未读数和首条未读入口均排除已撤回消息。

接收端提交已读后，Android 当前聊天会重新读取加密库的未读数。分页更新前，当前聊天暂存最近已提交的消息 ID，避免旧分页条目重复触发已读。会话列表通过 Room 的数据库变更更新。Mac 和 Windows 直接更新已提交的消息 ID，并从加密库读取该会话的最新未读状态。Windows 若读取摘要失败，沿用合并刷新流程重新读取会话。Android 发送端在当前视口内订阅有界的已发消息状态查询，回执显示取自已提交的状态。灰色单勾为已发送，绿色单勾为已送达，绿色双勾为已读。

三端仅在中继存储确认推进消息状态时刷新已发送标记。收件端回执也只推进状态。先收到已读、后收到送达时保留绿色双勾，同级或较低的回执不再写入消息状态或触发额外的回执通知。原来用于停止重试的发件箱和附件任务清理仍在同一事务内执行。

按可见范围和手动标为已读都在写入事务内排除自毁已到期或已超过本机保留期限的消息。可见已读提交失败时，三端在聊天仍可见且拥有焦点的情况下再尝试一次。重试前重新确认可见范围。安卓以当前可见消息的已提交状态为准，旧分页条目的失败状态不会压过重试后的状态。

## 三端视口边界

Android 和 Mac 在已读事务提交后撤掉指向该会话已读消息的系统提醒。Windows 在托盘提示实际弹出前重新核对消息状态和会话静音设置，过滤仍在等待显示的过期提醒。

- Android：读取 LazyColumn 的可见布局与 Paging 条目；排除失效索引及零尺寸条目。当前 Activity 必须 Resumed，主窗口持有焦点且聊天未被媒体/通话覆盖。系统/应用对话框使主窗口失焦时停止提交。可见 ID 集合稳定 150 ms 后提交；离开页面或失焦会取消该等待。
- Windows：遍历 ListBox 的实际生成容器，不把全部已加载数据当成可见。容器与 ScrollViewer 的横向及纵向区域必须相交；主窗口活动、可见且聊天未被覆盖时，按 150 ms 合并布局更新，只提交入站未读项。窗口失活或关闭会停止计时器。
- Mac：使用现有 SwiftUI 消息 frame preference，与当前滚动视口相交；聊天必须挂载、主窗口活动且非最小化，没有 sheet/modal、媒体或未最小化通话覆盖。150 ms 后再次确认可见 ID 与窗口条件，离开聊天会取消任务。

条目的纵向可见部分需达到 48 个逻辑单位，短于该值的条目需完整出现；Android 按屏幕密度换算。该门槛用于排除边缘露出的一小条。它不证明使用者理解了消息内容。系统彻底失陷等已排除威胁不在此属性之内；应用锁接入后还须共同检查锁定状态。

## 存储、队列与竞态

`privacy_preferences(id=1,read_receipts)` 保存开关，`read_receipt_suppression(peer,message_id)` 保存禁止以后披露的阅读标记，两者均在 SQLCipher 内。标记只含身份和消息 ID，不含消息内容或新的媒体所有者。

开关修改与队列处理在现有串行协调器中执行，单次数据库事务内完成。关闭时从待处理回执、未加密事件、尚未中继确认或因联系人关系暂停的 outbox 查找有关 Read，写入禁止补发标记，恢复必要的 Delivered 工作，删除尚未加密的 Read，并把已加密但未中继确认的对应 outbox 置为终止状态。已加密内容不原地修改，也不复用该事件 ID 重新加密。网络中已经开始的操作仍可能完成，不能承诺撤回已发送的事实。

关闭期间的本地阅读在同一事务内先写禁止补发标记，再更新本地已读状态。Read 创建、重复投递修复、最高状态选择和重试准备都同时检查开关与禁止标记。关闭后既不会排入新 Read，也不会因重复消息回填/重发旧的禁止状态。Delivered 不受该开关影响；回执不会触发回执循环。

清聊天历史保留禁止补发标记，与现有 inbox/回执去重信息共同防止迟到重复包恢复原本禁止的 Read。该标记不外键级联到正文；正文删除不能解除隐私选择。身份销毁会一并销毁所在资料库。后续协议元数据保留/回收必须共同处理去重与禁止披露标记，不能单独提前回收。最终保留策略仍未完成。

隐私撤销从待处理队列和带索引的 outbox 状态提取工作，通过回执事件 ID 索引关联，不对每条历史正文执行扫描。视口每批上限 100；原回执准备上限 64、重复重试间隔 30 秒继续保留。准备后取消仍会留下不可回滚的 Signal 发送步数；最终发送队列/保留策略复核及长期离线验收还必须覆盖这些取消间隔，不能将当前源码视作已完成互通证明。
