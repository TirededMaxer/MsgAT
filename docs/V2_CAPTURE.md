# 拍摄与录制

当前为源码编写阶段，未构建、未安装、未运行相机或做实际验收。聊天中的相机/录制是独立功能，不能由已有图库选择或语音通话代替。完整流程范围见 [聊天交互](V2_CHAT_INTERACTIONS.md)。

## 拍照源码

仅安卓提供聊天内拍照和录像。安卓已有相机入口、设备/权限状态、原生取景、拍摄、预览/重拍、取消与继续到原有发送确认的源码。拍后不直接发送；收件人、说明、按文件发送和定时/静默选项沿用发送确认，原聊天草稿/回复按已有快照规则提交。

| 客户端 | 拍照技术与数据路径 |
| --- | --- |
| Android | CameraX 1.5.3 内存 JPEG 回调；处理方向并将长边约束到 2560，编码 JPEG 95。临时内容位于应用内存中，用不导出的私有 ContentProvider 接入现有 URI 准备流程，不创建公共相册记录或明文临时文件。 |

Android 单张拍照内存源限 16 MiB、总活动图像内存源限 64 MiB。拍照结果长边上限为 2560 像素，使用 JPEG 的名称和 MIME。

安卓发送确认可裁剪和旋转静态 JPEG、PNG，适用于拍照、选图和粘贴。编辑来源上限 32 MiB、64 百万像素，生成图像长边上限 2560 像素。确认页更新预览和附件名称，支持撤销并恢复原图。编辑副本仅在私有内存中保留，随发送导入加密存储。头像裁剪、照片编辑和视频剪辑使用同一套窗口安全区，返回与确认固定在顶栏，避开状态栏、刘海和导航区。宽而矮的窗口将预览与可滚动的编辑控件并排排列。打开编辑器时收起说明键盘，返回后保留说明及已有编辑。头像预览与导出使用同一裁剪区域，照片预览使用黑底和可拖动的直角裁剪标记。

macOS 为选取、拖入和粘贴的静态 JPEG、PNG 提供相同的裁剪、旋转和撤销操作。编辑后的照片可与其他附件一起发送，编辑副本在导入加密存储前只保存在内存中。单个确认窗口中编辑副本合计上限为 64 MiB。

Windows 在 WPF 发送确认里为选取、拖入和粘贴的静态 JPEG、PNG 提供裁剪、旋转和撤销。图片按 EXIF 方向解码，保留 PNG 透明通道，编辑后沿用三端相同的图片尺寸限制。选中文件的编辑副本可与其他附件一起发送，原文件保持原样。编辑副本只在内存中保留，单个确认窗口中合计上限为 64 MiB。

安卓拍照和录像取景支持点按对焦测光与双指缩放，按当前摄像头能力启用。带闪光灯的摄像头可在拍照时选择关闭、自动或开启，录像时可切换常亮补光。切换摄像头会重新绑定取景控制，录像补光随取景退出关闭。

安卓发送确认可按时间范围修剪录制或选取的视频，提供时间线缩略图、片段预览和撤销。输入限 100 MiB、10 分钟，片段最短 250 毫秒。发送时 Media3 将所选片段重新编码为 H.264/AAC MP4，直接写入加密暂存。剪辑最长边限制为 2160 像素，勾选压缩后限制为 1280 像素。导出失败会中止这批附件发送，用户可撤销剪辑后重试。

Windows 可在发送确认里修剪本地视频。WPF 预览提供起止滑块、播放所选片段和撤销，WinRT 重新编码输出到加密暂存，限制与安卓一致。当前 Windows 输入要求原始画面方向正常，不处理需要旋转元数据的视频。导出失败时中止发送，不用原文件替代所选片段。

macOS 在 SwiftUI 发送确认里提供带缩略图的修剪界面、片段播放和撤销。AVFoundation 将所选范围重新映射到从零开始的时间轴，保留源视频方向，按同样的大小、时长和分辨率限制重新编码到加密暂存。导出失败会中止附件发送。

## 所有权与取消

- Android 内存源使用随机不可猜测的 URI、同 UID/当前身份检查和引用计数，不向其他应用授予权限。UI、预览读取和发送导入各持有自己的生命周期；最后一个所有者关闭后清除条目和字节。管道读源允许重新打开，以满足既有加密导入的两遍读取，不能在确认框一关闭就提前释放发送中的来源。
- CameraX 仅解除自己绑定的用例，生命周期结束不操作其他相机模块。关闭后的晚到回调丢弃结果并释放图像。安全区域应用到相机界面，避开系统状态栏/导航区域；实际尺寸仍待实机确认。
- 只在用户打开相机流程后请求相机权限。无设备、拒绝、设备占用或中断提供状态和重试/设置路径，不在本轮主动弹出系统权限窗口。

原有加密对象路径仍先登记暂存，再创建密文文件；对象清单、消息所有权和暂存移除在既有事务中提交。相机内存源没有引入新的持久媒体拥有表，也没有新增根种子副本。以上描述代码所有权，不承诺普通系统能阻止最高权限进程读取应用内存。

## 录制暂存核心后续（2026-11-10，只编码）

共享原生核心新增可定位读写的加密录制暂存文件，供三端编码器适配，不用先生成明文 MP4/M4A 再补加密。此处是核心阶段记录；三端拥有者和 Android 接入进展见下文。所有代码尚未编译或实际验收，不能声称录制已可用。

- 使用已有根身份所拥有的对象候选材料，通过单独 HKDF 域派生暂存密钥；沿用成熟 AES-256-GCM-SIV 实现，没有新增账户种子或自定义加密算法。
- 64 KiB 明文处理块只在内存中保留有限缓存。落盘记录为随机 nonce 与固定长度认证密文，认证绑定用途、候选 ID、容量、块序号和本进程当前块版本；重写使用新的随机 nonce 和块版本。
- 编码器可顺序写、定位回写文件头、读回已写内容和同步。最大暂存容量 100 MiB，每次 ABI 读写最多 256 KiB，每进程最多四个活动暂存。版本表、真实长度、密钥和句柄只在当前进程存在。
- 结束时刷出缓存、同步并冻结，冻结后拒绝写入。冻结来源之后应通过已有对象导入重新生成最终独立对象，原暂存候选不得直接作为消息清单发给对方。
- 路径沿用既有随机对象分片的 `.part`。接入端必须先用 `media_staging` 登记所有权，再调用创建文件；正常关闭先等待编码器/文件描述符和原生操作结束，再关闭句柄并让既有暂存回收删除文件。
- 当前没有新增持久媒体拥有表，不能将暂存候选插入消息/收藏拥有表。后台回收继续排除本进程的暂存所有权；崩溃重启后的旧拥有者条目按已有回收流程删除，不承诺恢复未完成录制。
- 暂存验证失败或 I/O 失败会使该暂存停止工作，不能将局部或未验证内容当成可发送来源。关闭会等待正在执行的原生操作，释放文件、处理缓冲与派生密钥，然后才允许拥有者移除暂存记录。

这些是代码行为与接入约束。后续编码必须保留三端拥有者和退出/Reset 的停止、排空接入；不得提前启动实际验收。

## 三端拥有者与录制接入（只编码）

- 三端新增录制拥有者，先登记候选暂存再创建加密录制句柄；冻结来源可持有独立读取租约。最终导入在原生核心中逐块解密/重新加密为新对象，不把暂存密钥或候选清单直接发给对方，也不要求整段录像常驻明文内存。
- 三端退出/Reset 先停止编码器并等待设备、描述符和正在运行的原生操作排空，再移除暂存。Windows 在 AppServices 关闭数据库前排空；Mac 使用异步 terminateLater 门槛，排空失败取消退出；Android 在 NettyClient 关闭其他存储拥有者前排空。停止回调只释放编码器、设备和流，不能反向调用正在等待回调的录制 freeze/close。
- Android 以 StorageManager.openProxyFileDescriptor 暴露可寻址的系统描述符。所有低层读写回到加密暂存；描述符自己的 HandlerThread 在 onRelease 后退出。最终媒体 URI 仍是不导出、同 UID/当前身份校验的私有来源，读流分别持有冻结租约。
- Android 语音使用 MediaRecorder 编码单声道 AAC/MP4（48 kHz、64 kbps），支持暂停/继续、结束、试听、取消，然后进入既有 caption/as-file/静音/定时发送确认。限制 30 分钟和 95 MiB 的编码输出。
- Android 视频使用 CameraX Recorder，HD/SD 质量选择、原生取景、前后摄像头选择、可选声音、暂停/继续、结束回放和取消；输出限制 10 分钟/95 MiB。达到正常上限后进行最终化，其他编码失败不交付发送来源。后台和来电状态触发结束录制，UI 消失发起独立的设备排空任务。
- Windows 的语音消息用 MediaCapture 将 AAC/M4A 写入加密流。Mac 的语音消息用 AVFoundation 产生 AAC 的 MP4 分片，直接写入加密暂存。两端均保留暂停、继续、试听、取消和发送确认，不请求聊天内拍摄权限。
- 安卓加号入口包含拍照、录像和录音；桌面端的加号保留录音和既有附件操作。拍摄、录制及发送确认层覆盖时不将底下聊天标为已读。上面属于功能接线，最终 Telegram 视觉、手势及动画仍在后续 UI 工作中。

三端空白输入框现在直接显示麦克风，有文字时切换为发送。加号始终单独可用，已有文字时也能打开附件菜单。安卓麦克风支持按住录制、滑向起始边取消、上滑锁定和释放后试听。锁定后可暂停、继续或结束，确认后沿用原有附件发送流程。点按仍可用录音对话框。Mac 和 Windows 使用各自的录音窗口，失去应用焦点时结束录制并保留可试听的结果。

三端的语音录制控件使用图标显示录制操作。结束后可试听、暂停和拖动进度。确定使用该录音后进入附件发送确认。

三端录制时显示真实麦克风输入的短波形，暂停时冻结，重新录制从空白开始。波形仅保留最近 28 个读数在内存。Windows 从当前 MediaCapture 的音频帧提取峰值，并在释放录音设备前停止帧读取。设备无法同时提供录音和音频帧时，录音窗口保留状态和计时。[Android MediaRecorder](https://developer.android.com/reference/android/media/MediaRecorder#getMaxAmplitude()) · [Apple AVCaptureAudioChannel](https://developer.apple.com/documentation/avfoundation/avcaptureaudiochannel/averagepowerlevel) · [Windows MediaFrameReader](https://learn.microsoft.com/en-us/windows/apps/develop/camera/process-audio-frames-with-mediaframereader)

安卓和 Mac 的试听区显示当前进度与总时长，加载或解码失败后可重新加载同一录音并尽量恢复到原位置。三端在打开定时等发送选项时暂停试听，关闭选项后可从原位置继续。确认发送时仍释放播放器，保留加密录音直到入队或取消。

试听或录制失败后可以重新录音。客户端先停止播放并释放上一份加密暂存，再返回录音准备界面。桌面端保留已选麦克风，开始下一次录制仍由用户点击，聊天草稿和回复继续保留。

三端通话在建立音频轨道前预留麦克风，等录制设备停止后才继续。交接期间和通话中禁止新录音。安卓有声录像同样参与交接。可正常封装的录音保留在发送确认前供试听。Windows 等待 WebView2 确认当前及待开启的音轨均已释放，再允许录音重新占用设备。

Android 展开的通话使用安全窗口，来电可覆盖现有的附件和录制对话框。拍照取景让出相机，有声或静音录像结束后保留已封装的结果。macOS 和 Windows 停止录音并关闭录制窗口以显示来电。录音可用时，退出通话并返回原会话后进入发送确认。切换会话、锁定或退出会释放待确认的录音，已有草稿仍走原有保存流程。三端通话期间暂停媒体和录音试听，用户可在通话结束后手动继续。

Android 的实际 seek/回写、不同厂商编码器行为、权限恢复、前后台和来电竞态仍须统一实际阶段验证。三端语音消息的编码、试听、播放与取消同样待统一实机验收。没有新增测试代码、运行构建或打开相机。

统一实际阶段需覆盖安卓摄像头与麦克风权限、设备切换、旋转、重拍、后台/锁屏、真实 JPEG 方向/质量；三端覆盖麦克风权限、录音、取消、退出、发送确认和接收播放。未新增测试代码或运行测试。
