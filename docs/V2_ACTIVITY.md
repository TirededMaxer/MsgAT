# 加密在线与输入状态

状态：2026-11-14 三端源码已接入活动状态和事件驱动的界面更新，待统一构建与实际验收。

## 用户行为

三端 Privacy 提供 Send read receipts、Share online status、Share typing status。在线与输入分享默认关闭。三个开关共用一次 SQLCipher 写事务，成功后才更新运行时偏好并刷新发送队列；读取或保存失败保留设置窗口并提示。已读的禁止历史补发规则见[已读隐私](V2_READ_PRIVACY.md)。

名称旁的状态文字只来自对方新近发出的、通过 Signal 认证的状态。Typing… 优先显示；在线显示还要求本机也开启在线分享。Online 表示对方报告前台活动，Offline 表示对方明确报告离开前台。过期、未知或未分享均留空，不把失联或中继存储确认误报为离线/在线。不保存最后上线时间，不上传正在输入的文字。

只有当前前台可见聊天主动请求在线状态；关闭自己的在线分享也停止主动请求。获准联系人收到有效请求后，且自己允许在线分享，才在短期兴趣窗口内回复/更新。输入分享独立控制，只由本机实际输入事件续期；草稿恢复不自动等于正在打字。切换聊天、失焦、媒体/通话覆盖、进入后台及发送清空会停止输入；没有后续更新时也会自行过期。状态是界面提示，不用于授权、密钥信任或消息送达判断。

## 加密与顺序

没有新增明文 presence 接口、静态 ECDH 旁路或自行设计的密码协议。`chat.activity` 与其他 V2 事件共用现有 libsignal、事务式本地队列、密文中继和 TLS。根种子、派生规则及硬件封装不变。服务端只按现有密文包处理，不解析活动字段。

共享 Rust `activity_transition` 维护每个对方身份的发送计数、接收高水位、最近接收 ID、最近发布与当前待确认事件。`chat.activity` 的严格字段为：`counter`（1…u32 最大值）、`online`（布尔或 null）、`typing`、`request`、`expires_at`。事件 ID 为 UUIDv4；应用事件解析仍拒绝重复键、额外字段和非整数计数/时间。

正文有效期最多 30 秒；输入提示最多至创建后 8 秒。接收端对较新计数才更新提示；过期或未来超过 5 秒的状态只推进顺序，不显示为当前活动。已经验证的陈旧状态仍可确认，以解除旧发送窗口。界面缓存把剩余期限换成本机单调时钟，重新启动不会从数据库恢复出一份看似仍在线的界面状态。设备时钟严重偏差会导致提示为空；这不是在线证明协议。

## 离线合并与确认

每个联系人最多保留一个等待**对方加密确认**的活动事件；中继返回已存储不解除此限制。后续本地变化先合并为当前意图。收到活动包后，用现有 `chat.receipt(state=delivered,message_id=活动ID)` 确认；这类确认不创建聊天气泡或通知，也不产生确认的确认。

同一活动需要重试时，沿用相同事件 ID、时间、密文和 Signal 发送步数，按 30 秒间隔恢复中继投递。没有因为一次输入刷新而不断推进新的 Signal 步数、丢弃旧包，再发送新包。尚未加密且已过期/被替代的活动可安全替换；已经加密的活动等确认后再生成最新状态。中继的队列项确认/过期后允许同一密文重新入队，所以长离线后旧的应用过期包仍能得到业务确认，随后再发当前状态。

每收到一个较新的活动，只保留其 Delivered 回执任务，清理前一个活动的回执与其缓存发送包：按本机记录的旧活动 ID 精确定位，不使用任意对方指定的消息 ID 批量清理。发送端只有收到该确认后才能继续，因而下一活动本身证明前一活动确认已到达。协议 inbox/已接收 wire 去重仍沿用原策略；最终去重元数据保留/回收尚未完成。

## 隐私、关系与资源边界

关闭分享既过滤未加密队列，也过滤已经加密、尚在 outbox 的有关活动。禁止重试旧的在线/输入内容；已经开始的网络发送或对方已经收到的内容不能撤回，最长显示期限仍受 30 秒/8 秒限制。重新开启时可以投递同一个过期密文以解除等待，但它不会被显示成新近状态；得到确认后才发布当前状态。

拉黑、删除和经根签名核对的身份撤销清除活动兴趣及当前发送状态，并清除界面缓存，保留顺序计数以拒绝旧状态复活。活动只面向已接受、未拉黑、未撤销的联系人。离开的旧聊天只能清除自己登记的聊天，不会把后来切换到的新聊天一并清掉。

`activity_peers`、`activity_watchers` 及隐私开关均在 SQLCipher 中；它们没有媒体对象所有权。公开提示仅在内存缓存，最多 128 个联系人；兴趣记录和待处理旧聊天集合各限 128。兴趣最多 45 秒，过期会清理。前台以 2 秒轻量调度驱动，普通在线续期不快于 12 秒，持续输入不快于 4 秒。每轮最多处理当前聊天与 31 个轮转联系人，离线旧项不能永久占住处理名额；后台不运行持续活动心跳；仍可对有效兴趣请求作出明确的 Offline 回复。默认关闭且没有待清理旧状态时，不为提示持续查询数据库或发新状态；持续输入只续本地期限，不让每个按键都触发数据库刷新。

调度工作合并入现有串行协调器，重复唤醒不堆积。前台、输入和当前聊天意图带本地修订号，处理中出现新变化时补处理。Android 随拥有者协程关闭，Windows 等待维护任务退出，Mac 取消并排空拥有者队列。

活动提交后通知当前聊天顶栏，三端按本机单调时钟等待下一次到期。输入提示到期时回到仍有效的在线状态，否则恢复连接提示。切换会话、窗口失活或收到更新时重新计算，桌面端按当前聊天和窗口可见性更新提示。语言跟随客户端的中英文设置。顶栏更新只读取内存，桌面端的活动包及确认沿用独立路径。

当前聊天显示输入状态时，状态行的三个点依次变化。在线与输入状态使用强调色，离线和连接提示使用中性色。动画仅随已经验证的输入状态显示，结束后恢复到当前有效状态。

中继仍能看到连接、包到达时间、发件/收件路由和密文长度；获准联系人也能从普通 Delivered 或连接交互推测某个客户端进程正在处理数据。关闭分享不等于网络匿名、不可流量分析或防止这些推测。此处隐藏的是主动披露的前台活动及输入状态。
