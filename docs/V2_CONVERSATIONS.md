# 会话整理与列表状态

状态：2026-11-10，三端源码已接入会话置顶/排序、归档、静音、本地未读标记、手动标为已读、文件夹规则，以及列表摘要/草稿。当前没有编译、检查或运行证据；后续统一编译报错时再排查。桌面继续保留原生双栏，当前功能入口不代表最终 Telegram UI 完成。

## 归档与静音

归档把聊天从主列表移到 Archived，不删除联系人或消息、不停止接收。归档可以随时撤回。新收到的未读内容会把未静音的归档聊天移回主列表；仍在静音期限内的聊天留在归档。操作的是本地列表偏好，不给中继发送归档/文件夹信息。

三端在归档或取消归档提交后提供短时「撤销」入口。安卓的滑动和菜单共用此入口。撤销仅在会话仍处于该操作产生的归档状态时提交，若新消息已将会话移出归档，旧撤销不会改变它。

有归档会话时，三端的「全部」页顶部显示归档入口和该分类的未读会话数。归档页内可直接返回「全部会话」，安卓也支持系统返回键。最后一条归档会话移出后，留在归档页显示空状态，短时撤销仍可用。桌面切换列表时继续显示右侧聊天。

从收藏、转发任务、发送队列、联系人和通话记录进入聊天时，沿用会话切换的编辑确认。定位当前会话内的消息会保留编辑。跨会话时，选择保留编辑会取消切换。进入原文前核对消息仍属于目标会话，而且未撤回或过期。

静音独立于归档，提供限时与长期选项。三端收到新消息时均从同一加密库的会话偏好判定通知是否被静音；真实消息、回执与未读计数继续保存。UI 在内存中更新期限显示，不靠每秒扫描数据库维持静音。收件人的会话静音与发件人的“无声发送”不同：前者关闭该会话通知，后者仍保留可见的无声通知。

会话列表菜单和聊天顶栏共用同一组通知选项。三端可静音 1 小时、8 小时、2 天或直到手动恢复。限时静音时菜单显示设备本地的恢复时间，用户可随时恢复通知或重新选择时长。

静音提交后，三端撤掉对应会话的消息提醒。Windows 同时移除正在等待显示的同会话提示。

## 未读与置顶

“标为未读”是自己的提醒标记，不回退历史消息的 Read 事实，不撤销已经发送的回执。打开聊天清除这一本地标记，正常自动已读继续遵守真实可见消息 ID 和前台/遮挡边界。

用户明确选择“标为已读”则是另一项手动指令：在一个事务内，按实际未读消息 ID 分批读取并调用原有回执规则，再更新这些消息和本地标记。事务期间不会把后来接收的新消息混进这次操作；内存每次只保留一批 ID。已读隐私关闭与禁止历史补发标记仍生效，不把手动操作变成隐私绕过。

主列表、未读筛选和归档沿用全局置顶顺序。自定义文件夹单独保存置顶及排序，可在各自的会话菜单中置顶、取消和上下移动。按规则加入的会话可以置顶，置顶不会改变它的成员关系。上下移动和拖动共用同一个事务，提交时重新读取当前分类中可见的置顶会话，按目标会话的 ID 移动。暂时不符合筛选条件的会话保留各自的排序位置。各列表依次按当前列表的置顶顺序、消息或草稿活动时间和会话 ID 排序。

文件夹改名或重排后，三端按文件夹 ID 保留当前分类。当前文件夹被删除时返回「全部会话」。安卓恢复界面时等待文件夹数据载入再判断原分类是否仍存在。

文件夹编辑器使用中英文界面，可按联系人显示名称筛选成员。筛选仅改变可见行，之前选中的成员继续保留，查询内容也不计入未保存的修改。修改名称、筛选规则或成员后，关闭编辑器、改选其他文件夹或新建文件夹时会提示保留或放弃尚未保存的修改。文件夹名称沿用存储层的 128 字节上限。

安卓在置顶会话的长按菜单中进入排序模式，长按列表行拖动，点完成或返回即可退出。Mac 使用原生列表拖动，Windows 从置顶行的把手开始拖动。两个桌面端在左栏完成此操作，Windows 的文件拖放仍沿用聊天附件发送确认。

## 文件夹与摘要

文件夹支持名称、显式聊天成员，以及 Include all chats、Unread only、Exclude muted、Include archived 规则。管理界面提供新建、编辑、排序和删除。删除文件夹只删除该分类和成员映射，聊天与消息保留。分类是当前身份的本地加密数据，不是同身份多端同步或服务器标签。

安卓通过顶栏下方的标签和横向滑动切换文件夹，各页独立滚动。Mac 使用横向可滚动的原生标签，并在系统开启减少动态效果时取消标签动画。Windows 使用会话栏左侧的图标栏，键盘方向键也可切换。三端在文件夹标签上显示该分类内的未读会话数。两个桌面端切换分类时保留右侧当前聊天。

桌面端可以用 Ctrl＋Page Up／Page Down 打开当前分类的上一个或下一个会话，列表随新选中的会话滚动。Windows 也支持 Alt＋↑／↓，Mac 在「聊天」菜单中显示这两项操作。未保存的消息修改沿用原有放弃确认，输入法组字期间不响应切换。 [Telegram Desktop 默认快捷键源码](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/core/shortcuts.cpp)

桌面端切换分类时只在左栏做过渡。Mac 保留原生列表及标签指示条，Windows 让新分类的列表与空状态一起短距离滑入。两端的归档入口和撤销提示使用短过渡。撤销提示占用列表下方的空间，最后一条会话仍可点击。过渡遵循系统的动态效果设置。

Windows 窄窗口保留双栏，并为会话列表和聊天区各留最小宽度。拖动分隔线或用方向键调整后按比例记忆宽度。窗口重新放大时恢复偏好的比例，双击分隔线回到默认比例。

Mac 主窗口缩窄时保留 SwiftUI 双栏。聊天区较窄时，通知和静音收进聊天操作菜单，语音、视频与搜索仍在顶栏。点击顶栏的头像、名称或状态可打开联系人资料。

安卓「会话列表滑动操作」默认切换文件夹，也可选归档。归档模式下横滑会话，达到阈值并松手后执行归档或取消归档，点标签仍可切换文件夹。置顶排序期间停用归档手势。 [Telegram Android 会话列表手势](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/DialogsActivity.java#L2285-L2322)

三端对全部、未读和归档使用界面语言，并在筛选结果为空时显示对应提示。两个桌面端未选中会话时在右侧显示选择提示。

在文件夹管理中，安卓长按行末把手拖动，Mac 在原生列表中拖动，Windows 拖动文件夹行。安卓和 Windows 在目标位置显示插入线，拖到边缘可滚动。松手后按两个文件夹的 ID 在一个事务中保存新顺序，标签随数据变更更新。上下移动按钮也使用同一写入路径。

会话行左侧为圆形头像，中间显示名称和摘要，右侧显示本地时间、置顶图标和圆形红色未读数。静音标记靠近名称，草稿摘要使用强调色。当天显示时间，过去六天显示星期，更早显示日期。安卓将搜索移到顶栏，将添加好友放到列表右下角。桌面端使用原生控件保留双栏和拖动行为。列表摘要显示最后一条内容、附件名或说明、撤回占位或待发送草稿。索引提供首条未读 ID，三端的定位记录见下文。

## 存储与生命周期

会话偏好、文件夹规则、成员、文件夹置顶、草稿活动和摘要视图都位于原 SQLCipher 库内。摘要字段只提供列表所需的消息预览和状态。文件夹置顶引用文件夹和会话，删除任意一方都会级联清理关联的置顶记录。

这些表不持有媒体对象，不改变 media_object_references，也不引入新的明文目录/缓存。Android Room 增加对应实体、已存在草稿表的镜像和 10→11 的保留式迁移，12→13 增加文件夹置顶表并更新摘要视图；没有开启破坏式回退。三个 schema 数组与 shared/storage/conversation-index.sql 记录相同结构。Android/Windows 的独立偏好写入所有者随客户端停止并排空，Mac 写入复用消息协调器；不在销毁资料库保护后继续后台写入。

会话摘要重新读取时按当前时间排除已到期的消息，包括预览、最近消息时间、最近消息回执来源和未读统计。安卓聊天内的未读数也使用会话摘要的口径。定时清理仍负责删除到期记录并触发列表更新。

## 即时更新

会话摘要、草稿、未读和文件夹变动接入提交后的数据失效通知。Android 的原始 SQL 协议事务另显式唤醒 Room 失效处理，分页消息和列表订阅据实际表变动更新。Windows 使用数据绑定优先级的固定短周期合并，并跟踪提交修订；更新期间出现的新提交会安排下一轮，不通过重置延迟一直等待“空闲”。Mac 对消息和列表订阅使用有界合并调度。

Windows 仅 Status/IsRead 改变时直接更新原消息项并通知绑定，保留媒体预览对象；其他内容变化仍走原来的行替换。查找现有消息改用按 ID 的映射，正常顺序不逐行做线性索引搜索。以上是代码行为设计，实际刷新延迟、滚动和闪白仍需在统一客户端阶段验收，不能当作已经通过。

## 2026-11-10：日期与未读定位（只编码）

三端新增会话内日期跳转和首条未读入口。日期按设备本地日历换算当地日开始，再以 UTC 毫秒查询加密库；找不到之后的消息时回到最近一条此前的有效消息。查询复用会话/时间/ID 索引，定位沿用已有分页历史窗口，不拉取整段聊天。

Windows 和 Mac 打开会话时新增首条未读锚点，Android 保留原有首条未读路由。Windows 延迟滚动绑定会话与导航代数，用户跳转或切换会话后不会被旧的“滚到最新”回调覆盖。手动定位不产生整段已读，仍由实际可见消息集合提交回执。置顶协议/表结构与 Android 存储帮助类开始编写，但尚未接入三端消息处理或 UI，仍属于未完成模块。全部代码未编译、未运行。

Windows 浏览历史时，收到新消息后仍以当前加载窗口的起点更新列表。越过窗口的新消息可从底部继续翻页，或用带未读数的按钮直达最新处。处于最新位置时，媒体、文字内容或输入区改变高度后仍跟随底部。

Windows 聊天滚轮读取系统的每次滚动行数，支持逐页以及细分滚轮输入。系统设为三行时保留每格 32 个逻辑像素的距离。触屏提供原生纵向滚动。

Mac 浏览历史时同样保留当前窗口的起点。滚动到这段历史的末尾才向后翻页，翻页后找回原来可见的消息。回到最新消息前，新到消息由未读按钮提示。

安卓浏览历史时使用消息 ID 保留列表位置。点「回到最新」会先比较当前页面首条消息与本地库最新记录，需要时从头重新加载分页，失败后可重试。会话、归档入口及回到最新按钮的未读数共用圆形徽标。


## 会话摘要

三端从同一条最新消息记录读取摘要类型和发送回执。会话列表根据类型翻译撤回、联系人卡片、通话和缺失附件的提示。用户发来的文字、附件说明和文件名继续按原文显示。存在草稿时优先显示草稿，并隐藏最新消息回执。
